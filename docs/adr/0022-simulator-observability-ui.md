# ADR-0022: simulator 観測 UI の設計原則 — オートマトン整合

- Status: accepted（2026-07-19、設計者確定）
- 出典: simulator-observability-ui ブランチでの simulator 改修（仕様スケッチ docs/examples/simulator.shitae）と、初版 UI への設計者フィードバック 2 回のヒアリング

## 背景: shitae の理論的下敷きはオートマトン理論

設計者明言（2026-07-19）。shitae の概念は次の対応で読める: component（と姿）= 状態、遷移語による遷移 = 状態遷移、frame スタック = プッシュダウン構成、presence gate = ガード条件、効果 = 遷移に伴う出力。simulator を含むツールの設計判断はこのモデルに整合させると意図に沿う。初版 UI の「ぎこちなさ」の正体は、この下敷きを押さえずに個々の仕様文言を局所的に満たしたことにあった。

ただし UI の表示用語は shitae の語彙（component・姿・遷移・スタック等）のまま使い、各ペインの説明文にオートマトンとしての読み方を一言添える（用語の全面置換はしない。設計者が比較の上で選択）。

## 確定判断

### 1. トレースログは実行された遷移の忠実な列 — back も追記する

物理戻るボタン・画面内操作の back() とも、成功時は通常の遷移イベントとしてトレースログへ追記する。トレース末尾除去（pop）はしない。undo はトレースログのイベントクリックによる巻き戻しに一本化する。

- 理由: トレース = 実行系列の記録。back で記録が削れるのは実行履歴の欠落であり、battle example の動作確認で設計者自身が「何事？」と混乱した実例
- スケッチ初版の「トレースログの末尾の遷移イベントを取り除く」文言はこの決定で改定済み
- これにより back(X) の多段巻き戻しでも「末尾が常に現在地」不変条件が自然に成立する（旧実装の pop 方式では破れていた）

### 2. トレースクリックの巻き戻しは全状態復元

stack・singleton 共有 variant・オーバーレイ集合をイベント時点のスナップショットへ復元し、トレースをそこまで truncate する。壁（barrier）は無視してよい（開発者向けタイムトラベルであり、アプリ内ナビゲーションではない）。

### 3. スタック表示を独立に持つ

トレースログ（実行系列）とは別に、現在の frame スタック（プッシュダウン構成）を左ペインに表示する。各 frame に @session マーカーと壁記号を付与する。exit/dismiss の対象セッション不在警告は「現在スタックに積まれているセッション一覧」を添えて、スタック表示と突き合わせて理解できる文言にする。

- 理由: 実行系列と現在構成は別物。セッション（begin マーカー）が可視化されていないと exit 系の挙動が理解不能（ログイン example の動作確認で実例）

### 4. 遷移マップは閲覧専用の状態遷移図

ノードは component 単位（全 module）、エッジは push/present/goto/switch の静的 target のみ（back/exit/dismiss・裸 ##variant の goto は含めない）。ノードクリックによるテレポート遷移は持たない — 状態遷移図に存在しないジャンプを UI が提供するのはモデル違反（設計者指摘「ありえないジャンプ」）。現在地ノードをハイライトし遷移に追随する。hover で情報プレビュー。レイアウトは GraphViz dot 風の簡易レイヤード（BFS rank + barycenter）を自己完結 JS で実装。

### 5. 画面カードの要素は階層、操作は対象に紐付け

要素の component 参照は入れ子で再帰展開し（循環ガード必須）、fold できる。操作は対象の要素に紐付けて表示し、有効範囲（document common / component common / variant 固有）はカテゴリ分けでなく各操作行のバッジで明示する。

### 6. レイアウト

全幅 3 ペイン: 左 = スタック + トレースログ / 中央 = 現在の画面（本体 + 掲示中）と遷移マップの独立スクロール 2 領域 / 右 = イベントログ + 画面外 component の姿切替（gate 試験用）。各ペインに見出しと役割説明を付け、エリアの意味が一目で伝わること。hover プレビュー等の付随情報はフレームアウトしない位置に出す。

## Consequences

- simulator.shitae（仕様スケッチ）は上記決定に追随して改定済み。スケッチと実装が食い違ったら本 ADR と直近の設計者判断が優先
- gate 観測パネル（スケッチ自註「微妙なら削除」）は存続。ただし名称と説明は用途（画面外 component の variant を手動切替して gate の効きを試す）が伝わる表記にする
- 今後 simulator に機能を足すときは、まず「オートマトンのどの概念に対応するか」を確認してから設計する

# ADR-0025: 履歴の閲覧と操作位置の変更を分離する

- Status: accepted（2026-10-20、設計案 v3.2 を仕様反映・実装するユーザー指示）
- 対象: GUI の表示・操作契約。言語構文、Session、scenario の意味論は変更しない。
- ADR-0024 の「履歴タップで巻戻し」の部分を置き換える。二列構成と新しい記録を上に置く順序は維持する。

履歴を調べる操作がそのまま実行状態の変更になると、閲覧と再開の意図を区別できない。GUI は表示専用の selection を持ち、既存 observation query の状態と handle のない当時の操作から履歴画面を描く。閲覧のための一時 seek は行わない。再開は移動元と移動先の確認後だけ seek する。

表示語は「操作を続ける位置」「見ている履歴の画面」「履歴の閲覧を終える」「この時点から続ける…」「位置の変更をやめる」に統一する。一記録内で保持・破棄が混在すれば「一部の結果は文章のみ」と表示し、点ごとの可否を残す。最後の結果が無観測のこともあるため、近道は「この操作の最後に保存された状態を見る」とし、実際の結果番号と状態番号を示す。

受理した実行commandは無観測でも閲覧と確認を解除する。拒否と読込失敗は旧Sessionと閲覧を保持する。成功load/resetで世代を更新し、旧IDを再利用しない。確認時は世代・revision・保持状態を再検証する。

履歴のanchorとfocusを保持し、折畳み・filterで消える点は親の記録見出しに復帰する。画面領域のスクロールは現在表示と閲覧対象ごとに管理する。表示状態はscenarioへ保存しない。

読込要約は読み込んだ時点の関係する部品の共有状態の一部であり、全一覧ではないと説明する。全状態の確認には現在の保存または元の読込ファイルと、同じ定義・実行版を使う既存CLI state照会を案内する。新しい全状態一覧GUIは追加しない。

仕様は [GUI履歴契約](../design/gui-history-contract.md)。設計元 A/B/C の内部整合レビューで、末尾無観測結果とfilter時のfallbackを明確化した。今回の利用評価対象はAIであり、人による評価を実装の待機条件にはしない。

# ADR-0005: exit(@S, 戻り先) は導入しない（見送り）

- Status: accepted — 見送りの決定（2026-07-12、設計者合意）
- 出典: stress-test 2026-07 — banking プローブ（複数入口ウィザードの出口固定）

## Context

exit(@S) は begin 地点へ戻る。複数の入口から同じウィザードに入ると出口が入口ごとに変わり、「出口は常にホーム」という要件が素直に書けない、という表現力ギャップが banking プローブで観測された。
被験者は `exit(@S, 戻り先)` 相当の戻り先上書き記法を要望した。

## Decision

導入しない。

- 戻り先の明示指定は「begin 地点へ戻る」というセッションの核不変条件に例外を作り、指定先の解決（スタックに無い画面・barrier の内外・子孫破棄との相互作用）という曖昧性の泥沼を持ち込む。
- 複合遷移の逐次意味論（findings B1、SPEC 改訂で明文化）により、**`exit(@S) ; push(固定先)`** が正攻法の慣用句になる — exit の子孫破棄保証を保ったまま、出口画面を決定的にできる。banking の被験者が懸念した「goto に切り替えると破棄保証を失う」問題もこの形なら生じない。

## Consequences

- SPEC のセッション節に上記慣用句を例として 1 つ置く（B1 の明文化とセット）。
- 実需（この慣用句で足りない具体例）が再度観測されたら再検討する。

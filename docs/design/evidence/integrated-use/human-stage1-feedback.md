# 人の予備的試用：S1 のフィードバックと最終判断

2026-10-18。このチャットで設計者から得た回答。実ブラウザで利用した人の申告であり、agent による再現確認とは区別する。人の操作は後にランダムウォークと明示され、操作経路・意図の分析と再保存依頼は撤回した。人の再保存物は受領しておらず、追加提出を待たない。JSON/モデル本文の非参照は依頼したが、本人から明示的な申告はまだ得ていない。

## 案内への追加質問

最初の依頼に対し「受取評価で何をすればいいのかいまいち理解しきれてないのでもうちょっとかみ砕いて教えて」と回答された。案内の説明を一回追加した。目的を「別の人から渡された操作記録を画面だけで理解し、続きを操作できるか」と言い換え、ダウンロード・読込の手順と、操作の流れ/現在状態/途中へ戻った形跡の3点だけを先に依頼した。次の一操作と再保存は後の案内に分けた。経路や条件名、期待の答えはこの補足では教えていない。案内理解のための追加質問1件であり、操作条件の選択誤りや製品への追加質問と同一に数えない。

## 初回回答（原文）

今は審査差し戻しを見てから戻って審査承認後までの流れを見ていたところなのはわかった。詰まったのは、「巻戻し/やり直し」でどこに跳ぶのかわかりづらい点。戻った先のイベント番号が示されてるといいのでは。またイベントをクリックしたときスクロール位置が最上部に戻されてしまうので変化がわからない。位置を固定し、アニメーションがあるといい。また、そこで巻戻しをイベントとして確定させてしまうのはつらい。イベント時点での画面をポップアップなり揮発可能な形で見たい。観測点・完了点・expesesなどの用語が理解しづらい。「分岐・破棄 15観測点（記録1 / 観測1、記録2 / 観測1、記録3 / 観測1、記録3 / 観測2、記録3 / 観測3、記録3 / 観測4、記録6 / 観測1、記録6 / 観測2、記録7 / 観測1、記録8 / 観測1、記録9 / 観測1、記録10 / 観測1、記録11 / 観測1、記録11 / 観測2、記録11 / 観測3）」などの情報が何を示してるのかわからないし、イベントクリックで巻き戻るのかこれらのfoldされた情報が出てくるのかよくわからない。右ペインにも情報が多すぎてよくわからない。文字がフラットに並んでいるので情報の種類が区別しづらいのも問題。視覚的な整理が必要。とはいえここらへんは分けて考えるべきデザイン課題。

## 受入への反映

- 流れの大筋を読み取れたことは本人の回答で確認できた。操作/条件の全順序、現在地の厳密な位置、破棄範囲、保存範囲まで正しく説明できたとは判定しない。
- 巻戻し先の分かりにくさ、イベントクリックの結果と展開操作の区別、スクロール位置の変化、用語、情報量と視覚的階層に理解上の障害が報告された。スクロール挙動や journal への記録は人の申告であり、この回答を受けた agent の再現検証は未実施。
- イベント番号による行先予告、位置維持とアニメーション、実行状態を変えない過去画面のプレビューは利用者の改善案。今回の評価だけで仕様・実装の採用を決定しない。
- 設計者の「分けて考えるべきデザイン課題」に従い、デザイン課題の抽出と評価記録を分ける。初回回答時点では製品変更や別 issue 作成には広げなかった。後続の明示依頼により、デザイン課題の別 issue 化だけを行う。
- 次の一操作の意図と内容、再保存、選択誤り/転記の有無は未確認。保存済み証拠で初回回答の不足を推測して補わない。

## 設計者の最終判断（後続回答・原文）

> ランダムウォークなのでそこは分析の価値はない

> うん、今の状態だと人間の読むものではないなと思った。デザイン課題の解決が先で、受け取り評価以前の段階。今のところの利用シーンとしてはAI用の分析ツールという位置づけでいいと思う。

## 今回の結論と依頼の撤回

人の操作は目的を固定した受取タスクではなく、予備的なランダムウォークだった。個々のクリック・最後の操作意図・経路・効率の分析は行わず、再保存の依頼も撤回した。大筋を理解したという発言はそのまま残すが、正式な独立受取評価の成功・失敗や達成率へ換算しない。

設計者の判断により、現状の利用シーンを AI 用の分析ツールと位置づける。人が読むためのデザインが未整備で、正式な人向け受取評価を進める前の段階とする。今回の人向け評価はここで打ち切り、全モデル配布、次の一操作・再保存、派生モデルの人による再検討を追加依頼しない。これらを受入済みや対象外へ変更せず、デザイン改善後に再評価する未達として残す。

使い勝手の指摘はデザイン課題の一次情報として保存する。行先予告・スクロール/変化の追跡・状態を変更しない過去画面の閲覧・用語と視覚的階層を [人向けデザイン issue](https://github.com/takasek/shitae/issues/35) に分離する。アニメーションやポップアップは改善案であり、具体方式の採用は別途設計する。今回の PR では製品実装・仕様は変更しない。

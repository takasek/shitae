# #27 統合利用評価の実施計画

2026-10-18。Claude session `13572828-69cf-490c-b312-b056cc2b21cc` から引継ぎ。設計者の回答を反映した実施版。一次情報は [#27](https://github.com/takasek/shitae/issues/27) の「受入：利用評価」。

## 確定した判断

- 人の受取人を入れる。設計者が S1 の段階1と派生モデルの再検討を担当する。処理系を知る利用者であり、初見利用者とは記録しない。
- 改善前後の比較 R2 は実施しない。速度改善や旧版との優劣を主張しない。
- Codex 自体は評価対象にしない。Claude 固有の `@playwright/mcp` 追加取得は引継ぎの前提にせず、既存の正規ブラウザ操作手段を用いる。
- 人の判断が必要な箇所と、人の判断により明確に手間を減らせる箇所だけ協力を依頼する。追加の工程承認は求めない。

HEAD と origin/main は `8c86f7cb1412e919554a41d65ff96f68f7e2b1bb`。#34 の merge を GitHub で確認（2026-10-17T21:39:48Z）。既存 branch `issue-27-integrated-evaluation` を引継ぐ。依存は frozen lockfile で準備し、`pnpm -r build` は成功。

旧版との比較は行わない。engine 不一致の診断検査は別項目として維持し、歴史的な旧処理系か metadata だけを変更した制御 fixture かを明記する。同じ scenario を異なる engine の互換再生成功の証拠にはしない。

## 担当と情報の分離

作者 AU、探索 EX、受取 R3 は別文脈で担当する。各担当は別 directory を使い、作者の会話・期待表・他担当の報告を受取人に渡さない。ハーネスによる読取禁止が未検証なら、その隔離を実施済みとは主張しない。担当に見える情報と実際に参照した情報を区別して記録する。人の受取人には専用の案内と配信用素材だけを渡す。

作者 AU は S1（経費申請、単一 module）と S2（備品貸出、entry と2 import module・simconfig）、S1 の一件の要件変更による派生モデルを書く。作者は探索を行わない。AI 作者による評価であり、人間作者の利用評価は未実施として残す。

探索 EX は問いと HTML から実ブラウザで探索し scenario を保存する。親は保存物から独立した期待表を固定し、受取開始前の SHA-256 を記録する。受取人に分岐の有無や答えを予告しない。

## 実施順

1. 作者のモデルを check し、固定処理系から HTML を生成する。S1/S2 全体で条件選択、結果途中と複数 seek、保存時 ghost、reset/手動試験、複数 module、組込み back/overlay を覆う。
2. 別担当が実ブラウザで探索して保存。操作条件・現在地・巻戻し先・破棄範囲・保存範囲の期待を受取前に固定する。
3. 人の R1 に S1 の HTML/scenario、目的・問い・版情報だけを渡す。scenario JSON・モデル本文・作者補足なしで経緯を説明し、次の一操作と再保存を行ってもらう。追加質問を記録する。
4. 回答と保存物を確定してから、全モデル/module/simconfig/CLI を渡し、別 directory で再生成と CLI replay を行う。別 process の export 全体を照合する。
5. R3 が S2 について同じ二段階の引継ぎを行う。engine、entry、module 増減、参照 module の source だけの差を試し、GUI の理由・次の行動・失敗後 Session 保持と CLI exit 1 を記録する。各不一致について、受取人自身が長い JSON の解析なしに再開か記録し直しかを選び、選択・参照情報・追加質問・選択の正否を記録する。
6. S1 派生モデルで元の検討手順を参照し、同じ問いを選び直して再検討する。再入力・転記・選択誤り・追加質問を記録する。自動 migration はしない。
7. 設計者に派生モデルの操作/条件の対応と #25 の set 対象名の相違を確認してもらう。答えの誘導を避け、受取の初回回答後に提示する。
8. acceptance.md に実ブラウザ・CLI・headless/VM・保存証拠照合を分けて記載する。独立レビューを実施し、PR と #27 本文への追記案を具体化する。新しい外部書込みは対象・内容を示して承認を受ける。チェックを付けず、issue close/merge はしない。

## 証拠と完了の境界

成果物はこの directory に置き、全結論を証拠ファイルへリンクする。CLI/headless の成功を実ブラウザや人の受取評価の代替にしない。人の未回答、未実施の人間作者評価、隔離の限界を OPEN として記録する。追加機能の実装や既存仕様の変更は今回の評価に含めない。

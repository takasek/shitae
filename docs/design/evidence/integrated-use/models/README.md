# 統合利用評価用モデル

作者は AI。これらは AI 作者が作成した評価用の素材であり、人間作者による利用評価を代替するものではない。人間作者による評価は未実施。

## S1: 経費申請の承認フロー

入口は `s1/expenses.shitae`。固定の出張交通費申請を審査する担当者向けの下絵。承認と修正依頼、領収書の照合、審査確認モーダル、修正コメントの通知を扱う。承認状況と領収書照合は、異なる担当者の出来事で更新される独立した状態である。

問い: 審査確認で各判断を選ぶと、どの結果がまとめて生じるか。審査中に領収書の照合結果が変わった場合、現在画面・承認状況・照合状況・通知を区別して説明できるか。確認画面と通知から開くコメント画面の終了はどう表されるか。

## S1 派生版

入口は `s1-revised/expenses.shitae`。変更要件は一件のみ。「審査結果の選択肢は、社内用語統一により『差戻し』から『修正依頼』へ改称する。状態名や結果処理は変更しない」。

問い: 用語変更後の審査選択肢と結果を確認できるか。変更前に記録された操作を、変更後モデルで利用する場合に何を確認すべきか。

## S2: 社内備品貸出

入口は `s2/main.shitae`。import 先はカタログと貸出窓口の二つ。プロジェクターの事前予約と、会議用スピーカーの当日貸出を扱う。固定の代表予約だけを共有し、任意件数の利用者・備品管理は扱わない。simconfig は確認画面の variant を分けて眺めるための表示設定である。

問い: 事前予約と当日貸出の導線・確認画面・終了方法はどう異なるか。予約できない場合や整備中の場合に表示される操作はどう変わるか。手動試験の記録を初期化し、別の貸出方法を確認する際、モデルと設定から何を確認できるか。

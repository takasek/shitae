# 予約派生モデルの独立再検討（追加確認）

対象: http://127.0.0.1:48827/tickets-v2.html
問い: 予約フローで確定前に日程を変更できるか。
変更要件: 日程変更の前に確認画面を表示し、そこで変更する / 取り消すを選べる。
参照した製品出力: /private/tmp/shitae-issue27-20261016-01a1433e/docs/design/evidence/provenance/browser-review.txt

## 観測結果

正規 CUA / iab の新規タブで開いた。原モデル、実装、JSON本文、oracle は読んでいない。旧scenarioの新モデルへのreplayはしていない。製品出力の検討手順を読み、画面に現れた選択肢から操作を選び直した。

1. 起動時は予約 / 今週。予約するの条件「空席」を選ぶと確認画面となり、「確定」と「戻る」が見えた。
2. 「確定」を選ばず「戻る」を選ぶと、予約 / 今週へ戻った。
3. 「日程変更」を選ぶと日程確認画面となり、「変更する」と「取り消す」が見えた。
4. 「取り消す」を選ぶと、予約 / 今週へ戻った。
5. もう一度「日程変更」を選ぶと、日程確認画面となった。
6. 「変更する」を選ぶと、予約 / 別日程へ進んだ。現在地表示は「変更する / 記録6 / 観測3 / 予約 / 別日程」、現在まで10観測点、ghost 0、破棄済み0だった。

問いへの回答: 観測した派生UIでは、確定前に「戻る」→「日程変更」→「変更する」で別日程へ進める。日程変更前の確認画面で「取り消す」を選ぶと今週を保つ。確認画面が追加されても同じ問いをUIだけで再検討できた。

## 人による選び直しの記録

操作順: 予約する [空席] → 戻る → 日程変更 → 取り消す → 日程変更 → 変更する。
文字転記: 0。再入力: 0。選択誤り: 0。追加質問: 0。旧手順の「確定後の途中観測点へ巻戻す」は使わず、今回表示された「戻る」を選んだ。日程変更が直ちに別日程へ進む旧手順から、日程確認の二択へ人が選び直した。

## 保存の未達

「シナリオを保存」を押す処理とdownloadイベント待機を1回だけ開始した。イベントとpathには各 timeoutMs:10000、CUA呼出しには timeout_ms:20000 を指定したが、ツール呼出しは応答せず235.8秒後にユーザーにより中断された。保存クリック完了、downloadイベント取得、保存実体の存在、パスのいずれも確認できていない。保存ファイルのパスは未取得であり、保存成功とは扱わない。追加のUI操作、再接続、同種待機は行っていない。証拠スクリーンショットの取得も未実施。

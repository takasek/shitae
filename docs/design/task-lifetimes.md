# タブと子作業の寿命を分ける

別タブから下書きを取り消しても、そのタブは残したい例です。`check` の成功だけではこの要件を確かめられません。深い子作業から初めて別タブを開き、遠隔取消した後の作業の木まで観測します。

## 入口が親子関係を決める

次の全文を一つの `.shitae` として保存して試せます。在庫タブへ最初から `switch` で入ります。証跡から初めて貸出窓口タブを開くと、最も近い switch 製の作業は `@inventory` なので、`@loans` はその兄弟になります（[SPEC の兄弟規則](../SPEC.md#switch中断と復帰)）。

```shitae
# 起動
> 始める -> switch(在庫, @inventory)

# 在庫
ナビ
> 下書きを始める(再開先.free?) -> present(下書き, @draft) ; set(再開先##下書き)

# 貸出窓口
ナビ
確定状態

# ナビ
取消
> 在庫タブへ -> switch(在庫, @inventory)
> 貸出窓口タブへ -> switch(貸出窓口, @loans)
> 下書きを再開(再開先.draft?) -> switch(下書き, @draft)
> 証跡を再開(再開先.evidence?) -> switch(証跡, @evidence)

# 下書き
ナビ
> 証跡を調べる -> present(証跡, @evidence) ; set(再開先##証跡)
> 確定を試す -> [成功] set(確定状態##確定済) ; exit(@draft) ; set(再開先##なし)
> [失敗] goto(##失敗)
## 編集中
## 失敗
失敗の説明

# 証跡
ナビ
> 下書きへ戻る -> exit(@evidence) ; set(再開先##下書き)
> 証跡確認を試す -> [失敗] goto(##失敗)
> [成功] goto(##確認済)
## 未確認
## 失敗
再試行の案内
## 確認済
証跡の説明

# 取消
> 下書きを取り消す(再開先.active?) -> exit(@draft) ; set(再開先##なし)

#! 再開先
## なし
free: 印
## 下書き
active: 印
draft: 印
## 証跡
active: 印
evidence: 印

#! 確定状態
## 未確定
未確定の説明
## 確定済
確定済の説明

# 印
操作できる印
```

「始める → 下書きを始める → 証跡を調べる → 証跡確認を試す／失敗 → 貸出窓口タブへ」を実行します。「残っている作業」または CLI の state で、`@inventory` と `@loans` が兄弟で、`@draft` とその子 `@evidence` が在庫側に残ることを確認します。「証跡を再開」は失敗状態へ戻り、「在庫タブへ」は在庫画面へ戻ります。タブへの復帰が最深の子への復帰を意味するわけではありません。

**反例**：入口の `switch(在庫, @inventory)` だけを `present(在庫, @inventory)` に替え、新しく始めて同じ経路を試します。証跡までに switch 製の祖先がないため、初めて開いた `@loans` は `@evidence` の子になります。貸出窓口から「下書きを取り消す」と、窓口まで下書きと一緒に消え、在庫へ戻ります。元の例では貸出窓口に留まり、下書きと証跡だけが消えます。

`present` 自体が誤りなのではありません。タブ全体を一緒に閉じる外側の作業には利用できます。この例の要件は「子作業を閉じても別タブは残る」なので、その内側のタブの基準を先に `switch` で作っています。

## 補助状態を更新する場所

`再開先` は実際の作業を自動検出しません。作者が再開先を有限個の variant に写した共有状態です。次の表は上の例の責任分担です。

| 操作 | 実際の作業 | 再開先の更新・期待 |
| --- | --- | --- |
| 下書きを始める | `@draft` を新規作成 | 下書き。なしのときだけ開始を許す |
| 証跡を調べる | 下書きの子に `@evidence` を作成 | 証跡 |
| タブ切替・再開 | 中断または既存作業へ復帰 | 更新しない。証跡の失敗状態も保つ |
| 下書きへ戻る | `@evidence` を閉じる | 下書き |
| 確定を試す／失敗 | 下書きを残して失敗状態へ | 下書きのまま |
| 確定を試す／成功 | 確定値を書き、`@draft` と子孫を閉じる | なし |
| 下書きを取り消す（現在地・別タブ） | `@draft` と子孫を閉じる | なし。確定状態は変えない |

取消列は通常部品 `取消` に集め、各画面に包含された `ナビ` から使います。包含しても新しい作業や共有状態は作らず、各結果の適用時点の実行状態へ作用します。ここでは名前付き `exit` で閉じる対象を指定しています。共通部品に裸の `goto(##状態)` を書く場合は、その部品自身でなく、その時点のアクティブ画面に作用する点も確認してください（[作用先の例](../AI_GUIDE.md#子に書いた操作はどこを変えるか)）。

新しい成功・取消・外部終了の操作を加えたら表に行を足し、実作業・再開先・確定値を別々に確認します。補助状態だけを手動変更すると、再開操作が存在しない作業を新規作成することもあります。presence gate はフレームの生存を検査しません。開始から通常操作で不変条件が保たれることを確かめてください。

この例は固定の一つの下書きです。任意の対象ID、実際の取引、全状態の正しさは保証しません。[長く残る確認の例](stale-confirmation.md)は、確認を作業の外へ残す場合と、作り直した作業を古い確認で取り消せるかという別の設計判断を扱います。

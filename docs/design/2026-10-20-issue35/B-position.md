# B 表示位置・焦点・変化を追う

この文書は設計時の比較・受入条件を保持する。2026-10-20の追加指示により仕様反映・実装へ進み、現行契約は [GUI履歴契約](../gui-history-contract.md) に集約した。人の理解評価は今回のAI向け実装の待機条件にしない。

表示名は [v3.2統一表](v3/terminology.md) に合わせる。「表示位置」はスクロール位置、「操作を続ける位置」は次の操作の開始点であり、同じ意味に使わない。

Aの閲覧方式と独立に、現行の詳細展開だけでもscrollTop720→0を再現した。原因候補は全DOM置換とscrollの未保存。測定結果は current-findings.md に記録している。

| 案 | 評価 |
| --- | --- |
| scrollTopだけ保存・復元 | 小さいが、上に記録追加/折畳みで同じ数値が同じ文章を指さない |
| 安定した行IDと画面内offset、focusを保持 | **推奨**。履歴追加と部分更新に耐え、静的表示でも位置が追える |
| 移動先へ自動スクロール＋アニメーション | 変化を強調できるが、調査位置を奪う。人の提案の一候補であり必須にしない |

履歴はSession世代＋step＋resultPosition＋observation refで行を識別する。詳細展開は押した見出しの上端を維持し、focusを同じ見出しに残す。閉じることやイベントfilterで対象が消える場合は親の記録見出しをanchorにし、その見出しの変更前offsetを復元する。filter controlにfocusがある場合はそのcontrolを維持し、表示設定だけでは閲覧selectionを解除しない。履歴追加時は最上部で追従中の人だけ新記録へ追従し、途中を読んでいる人はそのまま「新しい記録1件」を表示する。読込/resetで同一anchorが失われる場合は新しい現在地に移動し、その理由をstatusで告知する。

右側は操作を続ける画面と閲覧対象ごとにscroll位置を分ける。同じ対象の再表示は元の位置へ、別対象の最初の閲覧は見出しへ。閲覧を閉じると操作を続ける画面の元のスクロール位置を復元する。履歴側はその操作で動かさない。狭幅は一列にしても履歴と閲覧の往復位置・「履歴の閲覧を終える」の入口を保持する。

操作を続ける位置の変更は固定の現在地表示とテキストstatusで告知する。選択行は枠線＋「見ている履歴の画面」、実行点は別の「現在の操作位置」。色だけで区別しない。変化の演出は静的強調を既定とし、アニメーションは採用条件に含めない。キーボードで同じ入口へ到達でき、focusが消えず、読み上げ通知は詳細本文全量を読み直さない。

## 独立した受入条件と実装範囲

B1 実ブラウザで長い履歴の中段を展開/閉鎖/閲覧/復帰したとき、anchorのviewport内上端の差が通常2 CSS px以内（端のclamp時は理由記録）。同じscrollTopだけで判定しない。focusは起点または明記した親へ残る。

B2 記録追加、上部の開閉、イベントfilter、読込/reset、閲覧対象切替、長い画面、狭幅、拡大、キーボードに分けて確認する。失われたanchorのfallbackを目視確認する。動きを減らす設定でも情報が欠けない。

B3 初見の人が今見ている対象と操作を続ける位置の違いを説明でき、調査中の項目へ戻れる。人の過去のクリック経路は分析しない。

将来の実装はGUIの部分更新またはpresentation capture/restoreの拡張、anchor/focus/scroll管理と静的強調。Session保存形式へ表示位置を入れない。今回は比較用UIの限定操作のみブラウザで確認し、製品修正の受入とはしない。モバイル/支援技術の実検証は残る。

# 用語の変更提案（v3試行時の記録）

この文書は提案時の記録。現在の採用表記は [統一用語v3.2](terminology.md)。以下の「候補」「未確定」は当時の判断であり、現在の表示仕様ではない。

2人の初見subagentがv3の画面を操作して挙げた候補を整理した。これはAIの解釈と提案であり、非専門家の理解の実証ではない。正式な仕様語・JSONキーは変更していない。v3に既に入れた説明の改善と、今後採用を検討する名称変更を区別する。

原提案は [資料確認担当の17項目](usability/materials/report.md) と [用語担当の19項目](usability/terms/report.md)。両者は作者の会話、旧報告、ソース、互いの結果を見ずに試した。

## 推奨する整理

名称を短くするだけでなく、次の三つを一貫して区別する。

- **操作を続ける位置**：次の操作の出発点。記録番号と結果番号を添える。
- **見ている履歴の画面**：表示だけを切り替えた対象。続ける位置は変わらない。
- **この時点から続ける…**：続ける位置を変える操作。確認を開く。

状態を示すラベルには命令形を使わず、実際に押すボタンと区別する。「戻る」は対象を省かず、閲覧を終えるのか、業務画面内を移動するのかを説明する。

| 現在の語・表現 | 推奨候補と補足 | 判断・意味の注意 |
| --- | --- | --- |
| 実行位置／操作を続ける位置 | **操作を続ける位置**。「次の操作はここから行います」 | v3の説明を維持。「続ける時点」は短いが実時刻との混同があり、今すぐ全置換しない |
| 見ている時点／当時の画面／参照画面 | **見ている履歴の画面**。「見るだけで、操作を続ける位置は変わりません」 | 呼称を揃える候補。「過去の画面」だけでは現在位置より後の履歴を含めにくい |
| ここから操作を続ける（状態ラベル） | **現在の操作位置** | ボタンと同じ命令形を避ける。ボタンは「この時点から続ける…」と分ける |
| 変更せず参照に戻る | **位置の変更をやめる**。「見ていた履歴の画面に戻ります」 | 履歴の取消や業務の取消と混同させない |
| 後の履歴・戻れる | **後の履歴・参照／再開可**。「画面を見ることも、その時点から続けることもできます」 | 説明文を先に採用したい。短いラベルだけでは二つの可否を伝えきれない |
| 文章のみ | **文章のみ**＋「この時点の画面は残っていません」 | 維持推奨。片方は「記録のみ・画面なし」を提案したが、もう片方は記録に画面も含むと思われる点を懸念。仕様語discardedは技術詳細へ |
| 2結果／結果1の後 | **結果 2件／結果1の直後**。「この操作で起きたことを順に示します」 | 択一の2通りと誤読された。「変化2件」「更新2件」は状態変更以外の結果を落とすため採らない。1結果内の複数観測点は別に表す |
| 条件：指定なし | **選んだ条件：なし**（条件ラベルがない場合） | 「条件」は理由・成功・操作選択などを含みうるので一律に「理由」へ変えない。presence gateや自動判定と同一視しない |
| 状態点／観測点 | **戻れる地点**＋具体的な記録・結果位置 | 説明用の言い換え。正式語は技術詳細に残す。複数地点を一つの結果へまとめない |
| 新たに戻れる地点を作る操作 | **具体例を先に説明**。「この例では、申請を取り下げると後の画面を使えなくなります」 | 一語へ縮めない。「状態が変わる操作」は範囲が一致せず不適切。無観測no-opの例外は維持 |
| 画面を残さなかった操作 | **戻れる地点を作らなかった操作** | 保存し忘れのように聞こえる点を避ける。「移動しなかった操作」はこの例だけに通用するので一般名にしない |
| 前の画面に戻る | **前の画面へ（申請の操作）**。「履歴閲覧を戻す操作ではありません」 | 模型の操作欄で文脈を補う案。製品が扱うモデル由来の行動名を勝手に改名する意味ではない |
| 共有状態 | **共通になる部品の状態（共有状態）** | 何が共通かを説明する。他人への公開や全業務データを意味しない。「共通データ」「全状態」は広すぎる |
| 読込時点の要約 | **読み込んだ時点の状態（一部）**＋対象範囲 | 初期値と現在値は一致する場合もあるので「現在の状態ではありません」と常に断言しない |
| モデル | **画面と操作の定義（モデル）** | AIモデルとの混同を避ける。画面だけの定義には縮めない |
| シナリオ | **操作の再生ファイル（シナリオ）** | 自然文の利用シナリオとは区別する。モデル一式と同じ処理系の版も必要 |
| 処理系 | **実行プログラム（shitae）** | OSや端末そのものではない。CLIだけが処理系全体とは限らない |
| modelId／engineVersion | **定義の識別子／実行版の識別子** | 技術キーは併記し、完全一致を求める。見た目の短縮値だけで照合しない |
| module／component／variant | **所属／部品／選ばれている状態**という説明を添える | JSONキーは変更しない。moduleとcomponentの組で特定し、variantを任意のデータ値一般と呼ばない |
| seek | **操作を続ける位置の変更** | 通常の説明に英語の実装語を突然出さず、技術欄に対応を残す |

## 用語だけでは解けない指摘

訂正後の金額だけでは前後差分を組み立てる負担が残る。両担当は前の記録を追加で開いて比較した。「一万二千円 → 一万円」のような差分表示は次の設計候補であり、今回自動で機能追加していない。

CLI資料は揃い、資料担当は実値に到達したが、ブラウザだけで完結するわけではない。用語を平易にするだけでCLI/JSON/版照合の負担が消えるとは扱わない。

同一操作内で参照可能な結果と文章のみの結果が混在する場合、行全体の単一ラベルだけでは足りない。v3は結果ごとの可否を表示するが、見出しにも「一部の画面のみ」を示す案が残る。新しい経路の操作を一覧へ追記すること、参照対象の行を明示することも模型の今後の改善候補とする。

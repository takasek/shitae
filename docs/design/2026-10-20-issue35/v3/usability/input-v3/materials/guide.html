再現用の資料と確認手順

文書Aは大阪出張の申請、文書Bは画面外の領収書です。共有状態は複数箇所で共通になる部品の状態で、全ての業務データを含む意味ではありません。

1. 確認したい時点を選ぶ

時点対応する保存ファイル
読み込んだ時点（記録12・結果2）loaded.scenario.json
記録7・結果1から続ける状態（後の履歴は保持）resumed.scenario.json
そこから「前の画面に戻る」を試した後noop.scenario.json
さらに「申請を取り下げる」を行った後branched.scenario.json

参照している画面と、操作を続ける位置は別です。現在の状態を調べるときは、操作を続ける位置に対応するファイルを選んでください。設計デモに任意の位置を保存する機能はありません。上記は同じモデルで事前に生成・再生確認した資料です。

2. 同じモデルと処理系を用意する

モデル一式：expense.shitae（この1ファイル、importなし）。照合用の版情報。

modelId: 874fc8c77588d712fc22b3701a2f25c4c1e8d998999bb72415409be1a088570a
engineVersion: 278103a97da5319e8f97bb3218d6508b7cfd2a8d3ebd479aed3faf00f75f5116
モデルの入口: /Users/m5/.codex/worktrees/shitae-issue35-design/shitae/docs/design/2026-10-20-issue35/v3/materials/expense.shitae
利用できる処理系checkout: /Users/m5/.codex/worktrees/shitae-issue35-design/shitae
処理系commit: 022e8493e4bea272a552a5908abbd844ae5b1569
処理系入口: packages/cli/dist/index.js

今回の作業環境では上記checkoutにビルド済みの処理系と依存関係があります。別環境へ渡すときは同じcommitのshitae一式を用意し、そのcheckoutで pnpm install --frozen-lockfile と pnpm -r build を実行してください。モデル・シナリオだけを別版の処理系へ渡して一致すると仮定しないでください。

3. 読み込んで状態を照会する

以下は「読み込んだ時点」の例です。調べる時点に応じてファイル名を上の表から選びます。

cd /Users/m5/.codex/worktrees/shitae-issue35-design/shitae
node packages/cli/dist/index.js session /Users/m5/.codex/worktrees/shitae-issue35-design/shitae/docs/design/2026-10-20-issue35/v3/materials/expense.shitae --replay /Users/m5/.codex/worktrees/shitae-issue35-design/shitae/docs/design/2026-10-20-issue35/v3/materials/loaded.scenario.json

起動した同じprocessの標準入力へ、次のJSONを1行送ります。

{"id":"shared","command":"query","select":["state","metadata"]}

応答の data.metadata のmodelIdとengineVersionが上記と一致し、okがtrueであることを確認します。data.state.sharedVariantsが、画面外を含む全共有部品の状態一覧です。文書Bは module＝expense と component＝文書B の両方が一致する項目のvariantを読みます。同名の別部品と取り違えないでください。

同じモデル・版を用意できない、読み込みが失敗する場合は照合を止め、必要な組合せを作成者に確認します。保存ファイルの識別情報を書き換えて回避しません。

受け渡しのチェック項目

  • 対象時点と対応するシナリオ
  • モデルの入口とimportを含む一式
  • modelIdとengineVersion、使える処理系
  • 対象部品のmoduleとcomponent

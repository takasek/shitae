# v3.1 指定経路の回帰確認

初見試行 report.md とは別の追試。対象経路の指示を受け、次の予測を置いた。

1. 記録7結果1から記録10を参照し再開確認を開いた状態で「前の画面に戻る」を行う。移動先がなければ継続位置7結果1、後の履歴、参照10を維持する。開いていた確認が整合するかを観察する。
2. 同状態で取下げると新しい継続位置となり、旧確認と古い参照が消える。
3. 新しいタブから記録12結果1へ移動した場合、資料案内はその位置に対応するものを提示するか、用意がないことを明示する。
4. 分岐後に保持された記録3へ移動した場合、分岐を保つ現在状態と取り違える資料を案内しない。

## 実測

追試開始時、`cua.createBrowserTab('iab', 'http://127.0.0.1:8875/ui-proposal.html')` が `Browser is not available: iab` で失敗した。利用可能な接続を再確認したところ `cua.getState()` の browsers は空配列だった。ネイティブアプリ一覧にはChromeとCodexがあるが、指定されたIAB経路は利用できない。

このためv3.1の画面表示自体を確認していない。4経路はすべて未実施、AX・PNGは取得できていない。ソースを読む代替や別ブラウザへの変更は行っていない。UIの新たな不整合は判定不能。

必要対応: IAB接続を復旧したうえで再試行する。初見試行の証拠をv3.1回帰確認へ転用しない。

## 接続の再確認

親側では既存IABタブのreloadが成功したとの連絡を受け、指示どおり同じIABの利用可否をもう一度だけ確認した。`cua.listBrowsers()` は `[]` を返した。本agentでは依然としてブラウザ接続が公開されていないため停止を維持する。4経路未実施、v3.1画面未確認、AX/PNG未取得という制約は変わらない。

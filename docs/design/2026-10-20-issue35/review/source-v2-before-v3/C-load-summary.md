# C 読込要約の範囲と全共有状態への導線

## 現行契約と文言

現行 `summarizeLoadSingletons` は読込時点のmainとoverlayそれぞれについて、rootと包含treeに現れるsingleton、配置された操作のmember gateが参照するsingletonを集める。module+componentで各root内の重複を除く。画面外で無関係なsingletonは含まない。condition labelの式を評価して集める処理ではない。共有する値はvariantであり任意の業務データではない。

| 場面 | 現行 | 変更案 |
| --- | --- | --- |
| 0件 | 読込地点の画面と操作条件に関係するsingletonはありません | 読込時点の画面・操作条件に関係する共有状態（singleton）はありません。画面外の共有状態がないという意味ではありません。 |
| 1〜5件 | 読込地点のsingleton: 本体: … | 読込時点の画面・操作条件に関係する共有状態: 本体: … |
| 6件以上 | 読込地点のsingleton N件／読込地点のsingleton一覧 | 読込時点の画面・操作条件に関係する共有状態 N件／対象の共有状態を開く |
| 共通の補足 | なし | この要約は読込時点の値です。画面外も含む全共有状態の一覧ではありません。 |
| 共通の入口 | なし | 全共有状態を確認する方法 |

表示場所は「シナリオを読み込みました」の直下、現行要約の位置。共通補足と「全共有状態を確認する方法」は0件・少数・多数の全てに表示。長い操作説明は開いた時だけ示す。現行はcommand実行時にloadSummaryを消す（gui-session.js:201-204）。この寿命を維持し、表示設定の変更や閲覧だけで残る間も「読込時点」と示す。今の状態を知りたい場合は案内の現在保存経路へ誘導する。継続後は成功通知が消えるため、同じ「全共有状態を確認する方法」を「版の詳細・共有するもの」にも置き、現在の保存・照会に到達できるようにする。読込失敗時に成功の要約を出さない。

## 方式比較と推奨

| 方式 | 効果と限界 | 判断 |
| --- | --- | --- |
| 短い範囲説明＋既存state照会の手順 | 現行機能で達成でき、少ない変更。CLI未経験者には負担あり | **第一案として推奨**し、人の評価で不足なら次案を検討 |
| GUIに「全共有状態」読取専用一覧をオンデマンド追加 | HTMLだけで到達できる | 有用だが新しい表示機能。今回の短い案内で不足すると確認してから別の具体範囲として判断 |
| 常時全状態を表示 | 全状態が見える | 情報量を増やす。今回採らない |

「部品の状態を表示」は画面の部品・包含等を詳しく見る入口で、全共有状態を列挙する機能ではない。「画面外componentの姿切替」は試験値を変えるため、全共有状態の読取導線として案内しない。文書切替も実行状態を変えるので、純粋な照会の代替にしない。

## 開いた案内の具体的な本文

> 全共有状態はCLIのstate照会で確認できます。対象時点を選び、同じモデル一式と処理系を使ってシナリオを読み込んでください。読込時点を確認するなら元の読込ファイル、今の実行位置を確認するなら「シナリオを保存」で作ったファイルを使います。参照中の画面を表示していても保存するのは現在の実行状態です。
>
> 1. 「版の詳細・共有するもの」で完全なmodelId/engineVersionと必要なモデル一式を確認する。
> 2. 以下の `<モデルの入口>` と `<対象シナリオ>` を手元のパスに置き換える。
> 3. 起動した同じprocessへJSONを1行送る。応答の `data.state.sharedVariants` が、画面外を含む全singletonのvariant一覧。moduleとcomponentの組で識別する。`componentValues` は通常部品も含む別の一覧。

```sh
node packages/cli/dist/index.js session <モデルの入口> --replay <対象シナリオ>
```
```json
{"id":"shared","command":"query","select":["state"]}
```

HTMLだけではCLIに必要なモデル本文を取り出せない。モデル一式と同じ処理系がなければ「作成者から対応するモデル一式・処理系を受け取る」と案内し、UIだけで全状態確認が完結するとは言わない。照合が失敗したら元の組合せを用意し、自動移行や編集したscenarioで回避しない。手順へのリンクは生成HTML内に埋め込み、ローカルパスへの固定リンクや外部サイトがないと読めない説明にはしない。

## 独立した受入条件と実装範囲

C1 0件/1〜5件/6件以上/main+overlay/member gateだけに関係するsingleton/同名別module/画面外のBを持つモデルで、要約範囲・件数・折畳み・案内が正しい。件数は現行root別entryの合計であり、同じsingletonが本体とoverlayに出る場合は「表示箇所別N件」と明記する（唯一の共有値N個と誤記しない）。

C2 元ファイルの読込時点と、継続操作後に保存した現在時点を別CLIで照会し、state.sharedVariantsが期待したA/Bの値を含む。読取は実行状態を変えない。GUIの部品状態やgate試験を全一覧として誤案内しない。

C3 初見の人が「要約にないBは不明」と答え、必要なファイルがあれば案内だけで全共有状態へ到達し、なければ何を受け取る必要があるか説明できる。この小改善で十分かは未確認。HTML単体で完結する必要があると判明したらオンデマンドGUI一覧を別途設計する。

将来の実装範囲はloadSummaryHtmlの文言、成功通知直下の折畳み案内、件数単位と利用手順例。収集対象・保存契約・state APIは維持する。既存ガイドの更新は実装段階の対象候補であり、今回は変更案の提示に留める。

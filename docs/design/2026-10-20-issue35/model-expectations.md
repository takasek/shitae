# モデル検討の事前期待 v2

これは製品のSessionとは別のUI設計モデル。固定点B/C/D、未来の保持/破棄を代表する。任意数履歴、snapshot、revision、journal、export、実スクロールは言語で表現しない。ラベル条件は外部が選び、動的ガードでない。Cを破棄した後は「破棄済み」、対象が無効なら「対象が無効」を選ぶという環境前提がある。モデルが不正条件の選択を阻止する証明にはならない。

| 問い | 操作前に定めた期待 |
| --- | --- |
| Bを見て取消したら | 実行位置Cのまま。参照表示だけB→現在 |
| Bの再開確認を取消したら | 実行位置Cのまま、B参照へ戻る |
| Bへ移動を確定したら | 実行位置B、参照は現在、未来Cは保持 |
| BからCへ進んだら | 実行位置C、未来は保持 |
| Bから別操作したら | 実行位置新経路、未来Cは破棄。以後Cの画面参照不可 |
| Dと無観測結果を調べたら | 文章を読めるが参照/再開actionなし |
| 対象が無効になったら | 実行位置を変えず参照を現在へ戻し、古い参照を消して参照不可の説明 |
| 要約の案内を開いたら | 実行位置は不変。state.sharedVariantsへの手順が読める |

モデルの画面/overlayは情報状態の区別用で、製品のポップアップ採用を指定しない。実装の非変更契約はA1の別テストが必要。モデルのsetを製品のjournal変更と取り違えない。

## v1独立確認から追加した反例

Bで再開 → C参照 → 別の操作、の後は実行位置=新経路、未来=破棄、参照表示=現在。B/C参照overlayがなく、Cへ進めるactionも存在しないことを確認する。B→C→Bの参照切替では古い参照overlayを残さない。旧模型は `models/history-flow.shitae`、旧期待は `review/source-v1/model-expectations.md`、旧reviewは `review/independent-v1.md`。最終候補は `models/v2/history-flow.shitae`。ラベル条件を外部が適切に選ぶ制約はv2でも残る。

# 利用評価に基づく改善の検証記録

対象は「shitae 最新版の使い心地と概念整理」（2026-10-22、13ページ）。実装の起点は `604e19b7a1449739de2c3a3552f4baf8da18820b`。評価は AI によるツール支援の観察であり、人間の初心者による受入結果ではない。

## 変更

- 初回表示: 目的と対象外を短く表示し、保存・読込の入口を残しつつ版・保存範囲を折り畳む。現在の表示部品・操作を表示設定と手動試験より前へ移す。
- 条件付き操作: 行を白地の見出しと条件ボタンに分け、`[条件]で実行` と表示する。1クリックで分岐を実行する挙動は維持する。
- 初期化: 「初期状態から新しく試す…」で過去の画面の再表示・再開ができなくなることと、必要なら先に保存することを確認する。取消時は状態・履歴・保存内容・閲覧位置を変更しない。
- 履歴と保存: 結果は順に起きた内容であることを補足し、過去の画面の表示内容と現在のスタックを区別する。保存通知を「操作の再生ファイル」に揃える。
- 作者向け: AI_GUIDE に、子の定義にある操作がアクティブ画面を変える小例と、通常状態・共有状態の選び方を追加する。

言語構文、状態の寿命、履歴の保持方式、保存形式は変更していない。用語の全面改名、結果ごとの変更先を新たに表示する機能、初期化前の地点を保持する設計は今回導入していない。

## 追補の照合と次の改善候補

追加資料は「shitae 継続利用と設計変更の追補」と `shitae-revisit-20261022.zip`。モデル18ファイルのSHA-256は添付manifestと全件一致。v4-restored・v5・v6のCLI checkは診断なし。22再生ファイルを現在のCLIで全件再生し、すべて終了コード0、状態照会ok=true。添付のプログラムや生成HTMLは実行していない。[全件の再生結果](evidence/addendum-replay-summary.json)。再生成功は同じ処理系による照合で、独立した意味論の証明ではない。

`v5-overlay-escape` は現在の経路が `[0,1,4]` で、フレーム5（親4、@cancel、予約取消確認）が生存することを確認した。追補の「見えないが残っている作業」を具体的に裏付ける。

追補に基づく候補は次の順とした。1・2は下記の追加実装で対応し、3・4は未実装。

1. 履歴の折り畳んだ見出しに警告件数を表示し、詳細で診断コードと理由へ進める。自動展開や履歴移動はしない。
2. 現在のスタックと別に、残存フレーム・親子関係・状態を閲覧する領域を設ける。表示の選択だけではswitchやseekを呼ばない。共有状態と独立表示は別の寿命として示す。
3. 操作の詳細に定義元・局所上書き・作用先を区別して示す。scope名だけを一律翻訳しない。
4. 引継ぎ時の問い・開始状態・期待・不変条件を明示する。ログから期待を推測して捏造しない。

今回の折り畳みは技術情報の削除ではなく、版情報・状態照会・状態表示は引き続き開ける。追補の提案を、session終了時の自動削除やpresentによる全操作遮断へ読み替えない。

# shitae を読み書きするための定義（AI 向け）

あなたは UI ラフスケッチ言語 **shitae** の読み書きを行う。shitae は、画面・表示要素・インタラクション・遷移を、実装や Figma の前段でテキストで素早く描き、人と AI が往復で揉むための言語である。厳密な仕様ではなく**ラフな下絵**であることを最優先する。

## 全体像

- **component**（`#`）が唯一の単位。画面も部品も区別なくすべて component。トップレベルで遷移先になれば「画面」、要素節に置かれれば「部品」に見えるだけ。
- **姿**（`##`）＝ component が取りうる見た目の状態（読込中／表示、未フォロー／フォロー済 など）。状態を `if`/`guard` ではなく姿の列挙で表す。閉じた種類の列挙（画像／動画／広告 など）にも使える。
- すべての名前は**対等**。特権的な組み込み component はない（`button` と書いても「ボタンという名の component を置いた」だけで特別な意味はない）。定義があれば自作、なければ未定義（ラフに置いただけ）。
- **ラフであることが機能**。未定・穴は専用記法を使わず**自然文**で書く。
- 構造は明示的な記号で表し、**インデントに意味はない**。
- 実行の起点：**エントリポイントはファイル先頭の component**。姿を複数持つ component の**初期姿は最初に定義された `##`**。

## 記号と予約語

記号：`#`（component）`##`（姿）`>`（インタラクション行）`:`（alias）`*`（集合・前置）`{}`（inline）`.`（要素参照）`->`（行動と結果の境界）`;`（結果の区切り）`[]`（条件ラベル）`?`（存在ゲート）`"..."`（クオート名）`@`（セッション）`::`（モジュール）`//`（コメント）

予約語：
- 遷移語（コア）：`push` `back` `goto` `exit`
- 遷移語（複合）：`present`（壁ありセッションの開始）`dismiss`（直近の無名セッションの破棄）。糖衣ではなく、コア 4 語に「壁」を組み合わせた複合語（壁は `push` 単体では表せない）。
- 構造：`import` `as`

これ以外のキーワードを発明しない。表現できないものは自然文で書く。

## 構文（最小要約）

```
# 画面名                       ← component 定義
## 姿名                        ← 姿（省略可。無ければ単一の姿。## より前は全姿に共通）
要素                           ← 要素節：component 名を並べる
別名: 要素                     ← alias（左が呼び名）
*要素                          ← 集合（前置 *）。`*手札: カード` も可。参照すると 1 インスタンス
入れ物: { 子; 子 }             ← inline component（要素のみ）
"長い 名前"                    ← 空白を含む名前はクオート（エスケープなし。全 name 位置で有効）
> タップ(対象) -> 結果 ; 結果     ← インタラクション行。行頭 `>`（`>` 後の空白・インデントは非意味）。要素行と `>` 行は混在可（推奨は要素を先に書く）
> 更新 -> リストが更新される      ← 対象を取らない行動は括弧省略
> タップ(自分.フォロー) -> push(編集)   ← 要素参照は alias 名で 1 段（component名.要素alias）
> タップ(サムネ) -> push(画面##姿)     ← 姿参照は ##（同一 component 内は ##姿 と書き component 名を省略）
> タップ(対象?) -> 結果            ← `?` は存在ゲート。対象がその姿にある時だけ有効（opt-in）。`?` 無しは常在
> タップ(ログインボタン) ->
>     [成功] 認証する ; present(ホーム, @loggedIn)   ← `->` ありは新規インタラクション行
>     [失敗] 認証エラーを表示する                     ← `->` なしの継続行 ＝ 直前の結果列に result を追加
> ... -> push(確認, @checkout)    ← セッション開始（push/present の第2引数）
> ... -> exit(@checkout)          ← 名前付きセッションを破棄（begin 地点へ）
import auth as auth             ← モジュール（ファイル）読み込み
> ... -> push(auth::ログイン)      ← 別モジュールの component を :: で参照
// コメント                     ← 行頭・行末どちらでも
```

## 遷移語の使い分け

- **`push(X)`** … X へ進む（積む。`back` で 1 つずつ戻れる）。
- **`back()` / `back(X)`** … 直前へ／component X まで戻る。**引数は常に component**。
- **`goto(X)`** … 現在を X に置き換える（積まない、戻れない）。同一 component の姿替え `goto(##姿)` にも、別 component への置換 `goto(ホーム)` にも使う。
- **`exit(@S)`** … セッション @S を破棄して begin 地点へ戻る。**引数は常にセッション**。
- **`present(X)` / `present(X, @S)`** … モードに入る（モーダル、ログイン後フロー等）。壁ありセッションを一語で表す複合語（`push` 単体では壁を表せない）。
- **`dismiss()` / `dismiss(@S)`** … 直近のモードを閉じる／@S を破棄。

`back`（画面方向）と `exit`（セッション方向）は予約語で役割が決まる（`@` で見分けるのではない）。`dismiss`（無名・引数なし）と `exit`（名前付き・@S 必須）は別物。

### セッションと「back の壁」

セッション `@S` ＝「開始してまとめて破棄する期間」。`push(X, @S)` / `present(X, @S)` で開始（その遷移が begin）、`exit(@S)` / `dismiss(@S)` で破棄（begin 地点へ）。同名が複数あれば LIFO で直近を破棄。`goto` はセッションを開始できない（積まないため begin 地点を残せない）。

「back の壁」と「セッション」は直交：
- **`push(X, @S)`** … 壁なし＋セッション。経路を `back` で遡れる＋ `exit(@S)` で一気に戻れる（閲覧フロー）。
- **`present(X, @S)`** … 壁あり＋セッション。モード内で `back` しても外に出ず、`dismiss`/`exit` で抜ける（モーダル）。

`present` はモーダルに限らず「モードに入る」遷移全般に使う（`present(ホーム, @loggedIn)` ＝ ログイン後モードに入る、`exit(@loggedIn)` ＝ 抜けてログインへ）。

### スタックと戻り先

処理系はスタックに **(component, 姿) の組**を積む（`push`/`present` が積み、`back`/`exit`/`dismiss` が戻る）。戻り先はその組が積まれた時点の姿。`goto(##姿)` は積まず、現在のエントリ（スタック最上段）の姿を書き換えるだけ。

戻り先が無い（back の壁・該当する `@S`・積む先のどれも無い）ときの `back`/`exit`/`dismiss` は **no-op**。ツールは警告してよいが、エラーにはしない。

### 共通と姿固有の優先順位

共通節（`##` より前）と姿固有節に**同じ (行動, 対象参照) の組**が両方にあれば、姿固有側が共通側を **shadow**（特化が勝つ）。外部からの要素参照が部品定義側の挙動を上書きするのと同じ原理。

### 分岐の意味論

結果列は **(条件, 結果) の組の集合**。`[ラベル]` 付きの result は `(そのラベル, 結果)`、ラベルなしの result は直前のラベルを引き継ぐ（最初のラベルより前なら常に成立）。存在ゲート付きの行動 `A(C?) -> R` は `(exists(C), R)`（`?` 無しは常在）。

条件は 2 種類が重なるが、どちらも評価しない：対象の存在（`?` を付けた対象だけに掛かる opt-in のゲート。その対象を置いた姿でだけ行動が成立する）と、分岐ラベル（`[成功]` 等。動的だが注記に留め、選択は外部が決める）。状態機械のガード（式を評価して可否を制御）とは異なる。

矢印 `->` は 1 行に 1 つだけ（`-> R -> R` は構文エラー、`;` で並べる）。`[ラベル]` のスコープは**次のラベルが現れるまでの結果列**（`;` と改行の継続行がともに result の区切り）。最初のラベルより前の result は常に成立。

## チェックリスト（書いたあと確認する）

- [ ] **姿参照は必ず `##`** か。`goto(表示)` は「表示という component へ」になり姿替えにならない。姿替えは `goto(##表示)`。
- [ ] **遷移には遷移語**を書いたか。`-> 完了`（遷移語なし）は副作用（「完了する」）と解釈され、`完了` 画面への遷移にならない。遷移なら `push(完了)`。
- [ ] **要素参照は alias 名**か。種別名や生の要素名では引けない。参照する要素には alias を付ける。
- [ ] **`present` したものは `dismiss`/`exit` で閉じる**か。モーダル内から `goto(別画面)` すると、そのモーダルが下に残ったまま中身だけ置き換わる。閉じてから遷移するか、姿（`##`）にする。
- [ ] **セッションの開始は `push`/`present`** か。`goto`/`back` でセッションを開始しない。`back` にセッション（`back(@S)`）を渡さない（破棄は `exit`/`dismiss`）。
- [ ] **遷移先の component は存在する**か（または未定義を承知で置いているか）。
- [ ] **inline `{}` に姿やインタラクション行を入れていない**か。要素のみ。挙動が要るなら名前付き `#` に昇格。
- [ ] **`.`（要素）と `##`（姿）を合成していない**か（`画面##姿.要素` と書かない）。
- [ ] コメントは `//` か（`#` はコメントに使わない）。
- [ ] 未定を `???`/`(未定)` でなく自然文で書いたか。
- [ ] 状態を `if`/`guard`/変数でなく姿で表したか。
- [ ] **インタラクション行に `>` を付けた**か。
- [ ] 分岐は 1 行 1 ラベルグループの継続行（`->` なしで書く）にすると読みやすい。
- [ ] `?`（存在ゲート）は opt-in で必要な行だけに付けたか（既定は常在で `?` 無し）。

## 扱わないもの

状態の条件式・ガード・並行状態・変数・props・引数（→ 状態機械の領分）／レイアウト・見た目・寸法（→ Figma 等）／component の型・プロパティ定義／atom・molecule のような粒度。

```
# プロフィール

> タップ(フォロー) -> フォローする ; goto(##フォロー済)
## フォロー済
解除
> タップ(解除) -> フォローを外す ; goto(##未フォロー)

# 一覧
*サムネイル
> タップ(サムネイル) -> push(プロフィール)
```

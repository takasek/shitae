# shitae DSL v3 設計書 — 表現の穴を塞ぐ 6 つの改訂

日付: 2026-07-11
状態: 設計者承認済み（ブレインストーミングで各論点を個別に裁定）
前提: 記法 v2（SPEC.md 反映済み）を基点とする改訂案

## 背景と動機

SPEC・example 2 本・PRIOR_ART の総点検で見つかった問題は 3 群に分かれる。

**表現できない頻出パターン**。(1) タブナビゲーション — `goto` は積まない置き換え、`push` は積む一方で、「離れても状態が残る並行文脈」を表す語彙がない。(2) どこからでも起こる遷移 — deep link・プッシュ通知・強制ログアウトを書く場所がなく、全画面に転写するしかない。(3) 部品インスタンス間の姿の同期 — 画面 A でフォローしたら画面 B のカードも変わるのか、SPEC が無言。

**罠と dogfooding の穴**。遷移語を書き忘れると黙って副作用扱いになる（SPEC 自認の「ラフさの代償」）。また `?`（存在ゲート）と `import`/`::` は「全機能の通し書き」を謳う example-battle にすら登場せず、仕様が例でカバーされていない。

**失われた物語性**。uiflow が持っていた「この順に操作するとこうなる」という筋を記述する層がない。simulator 資産があるのに、シナリオを残して回帰検証する手段がない。

設計者の裁定により、以下の 6 点を採用する。

---

## 1. `switch(X, @S)` の導入とフレーム木

### 問題の本質

現行セッションの動詞は開始（`push`/`present`）と破棄（`exit`/`dismiss`）のみで、「離れる＝破棄」しかない。タブとは「破棄せず中断できる名前付きセッションの辞書＋復帰の一手」であり、欠けている動詞は**中断と復帰**である。先行技術では GoRouter の StatefulShellRoute（タブごとの並行スタック保持）、statechart の history state（離脱位置を覚えて復帰）が同概念で、「実装ナビの語彙を設計層に引き上げる」という shitae の既定路線（PRIOR_ART 系譜 C）に乗る。

### 内部モデル: 単一スタック → フレーム木

- ランタイム＝木。ノード＝**フレーム**（(component, 姿) のスタック 1 本＋壁の有無）。ルート＝エントリの無名フレーム。アクティブなフレームは常に 1 つ。
- `push(X, @S)` / `present(X, @S)` は現在フレームの**子**フレームを作りアクティブ化する（begin 地点＝親フレーム内の位置）。壁は present のみ。従来挙動は木が一本道のケースとしてそのまま保存される。

### switch の規則

- **`switch(X, @S)`** — @S が生存していれば現在フレームを**中断**（破棄しない）し、@S の中断位置（スタック先頭の (component, 姿)）に復帰する。X は無視する（lint で不一致警告可）。@S が無ければフレームを新規作成し X で開く。resume-or-create の一語。
- 引数形は `switch(X, @S)` の 1 形式のみ。resume 専用形 `switch(@S)` は作らない（常に resume-or-create なので初回と復帰を書き分けなくてよい）。
- 壁: あり（present と同様）。タブ間を `back` で漏れない。
- 遷移語は計 7 語になる: コア `push`/`back`/`goto`/`exit` ＋複合 `present`/`dismiss`/`switch`。

### 兄弟規則（新規作成時の親の決め方）

switch でフレームを新規作成するとき、**現在フレームが switch 製なら兄弟（同じ親の子）、switch 製でなければ子**にする。

理由: 単純に「常に現在フレームの子」にすると、ホーム→検索→マイページの順に switch したとき @tabMy が @tabSearch の子になる。木の形が訪問順に依存し、`exit(@tabSearch)` がマイページを道連れにする事故が起きる。兄弟規則ならタブは訪問順によらず横並びで安定する。

### 破棄と走査

- `exit(@S)` は @S と**その子孫を全部**破棄する。「ログアウトでタブ全滅」が規則追加なしで導かれる。
- 破棄済み @S への switch は再作成。「再ログインでタブがまっさら」も導かれる。
- 中断中（非アクティブ）の @S への `exit` は**可**。裏でタブを破棄し、画面は動かず現在地維持。
- `back()` / `dismiss()`（無名）の走査は**アクティブパス**（現在フレーム→祖先）のみ。中断中の兄弟は見ない。`exit(@S)` / `dismiss(@S)` はまずアクティブパスを「新しい方から最初の @S」で走査し、見つからなければ木全体から探して遠隔破棄する（画面は動かない）。

### タブの慣用句と「最初のタブ問題」

タブ 1 だけが switch 製でないと、ホームタブのタップが `switch(ホーム, @tabHome)` で重複フレームを作ってしまう。解決は慣用句側: **ログイン成功時に `present(ホーム, @tabHome)` でホームタブ自体を名前付きフレームとして入場する**。ホームタブが他タブの親（錨）になる非対称は許容する（iOS 実機の「ホームタブがルート」挙動と一致）。

```
# ログイン
> タップ(ログインボタン) -> [成功] present(ホーム, @tabHome)   // ホームタブ＝錨フレーム

# ホーム
タブバー
> タップ(タブバー.検索) -> switch(検索, @tabSearch)
> タップ(タブバー.ホーム) -> switch(ホーム, @tabHome)   // 生存中なので復帰、重複生成しない
> ログアウト -> exit(@tabHome)   // 子孫ごと全タブ破棄
```

### トランスパイラへの影響

XState 変換は history state に素直に写る（statechart に元々ある概念）。mermaid はエッジ追加のみ。simulator はフレーム木への改造が必要。

## 2. document 共通ブロック

最初の `#` より前に書いた要素行・インタラクション行を**全 component 共通**とする。既存の対称性（`##` より前＝全姿共通）を 1 段上に伸ばした形で、新しい構文記号はゼロ。

```
> プッシュ通知をタップ -> push(記事詳細)
> セッション切れ -> goto(ログイン)

# スプラッシュ
...
```

- deep link・通知・強制ログアウトの置き場になり、「エントリポイントが 1 つしかない」問題も同時に解決する。
- shadow 規則は既存の「特化が一般に勝つ」を document レベルへ拡張する: 姿固有 > component 共通 > document 共通。（行動文字列, 対象参照）完全一致で特化側が勝つ。

---

## 3. 姿の独立性の明記

「各インスタンスの姿は独立。インスタンス間の同期はデータの関心であり実装の領分」と SPEC に 1 段落追記する。言語で共有姿を導入するとデータ導入の裏口になるためやらない。simulator 上で不整合が見えるのはラフの代償とする。

---

## 4. lint: 遷移語忘れの検出

checker に「結果の自然文が既存 component 名と完全一致したら warning（遷移のつもりなら `push(X)` と書く）」を追加する。言語は変えない。`-> 完了` 問題（SPEC 自認の罠）をツール側で潰す。

---

## 5. `?` の説明強化と example 追加

`?`（存在ゲート）は現状維持。ただし motivation を SPEC に明記する: 「`?` なし＝対象不在でも有効」がデフォルトなのは、要素行に書いていない未定義対象への行動（ラフさの核）を許すための opt-in 設計である。あわせて example に `?` の使用例を追加し、dogfooding の穴を塞ぐ（`import`/`::` の example 追加も同時に検討）。

---

## 6. シナリオ層 `.stroke`

本体 `.shitae` の文法は不変に保ち、シナリオを別ファイル形式で導入する（「安易な機能追加を避ける」哲学との両立）。名前は下絵のアナロジーに合わせ **stroke**（下絵を一筆でなぞる）。

```
stroke 初回ログインから対戦まで
> 起動完了
> タップ(ログインボタン) [成功]     // 分岐はラベルで選ぶ
expect ホーム
> タップ(対戦をさがす)
expect マッチング##検索中
```

- 拡張子 `.stroke`。1 行＝simulator の選択肢を 1 つ選ぶ（行動文字列＋対象で一致。分岐のある行動は `[ラベル]` を添えてどちらに転んだかを選ぶ）。
- `expect component##姿` ＝ 到達検証。落ちたら仕様変更がシナリオを壊した、という回帰検出になる。
- 対象 `.shitae` は CLI 引数で結ぶ（`shitae stroke battle.shitae battle.stroke`）。stroke ファイルは対象を知らない疎結合。
- `stroke` / `expect` は stroke ファイル内だけの語彙で、本体の予約語は増やさない。記号（`>` `[ ]` `##`）は本体と共通。

---

## 検討して採らなかった案

- **タブを姿の慣用句で表す**（言語変更なし）: 「どのタブにいたか」までは表せるがタブ内スタックの独立保持が表現不能。switch 導入により不要。
- **`?` の削除またはデフォルト反転**: 反転は未定義対象への行動（ラフさの核）を殺すため不可。削除は使用実績ゼロを理由に提案したが、設計者裁定で維持＋説明強化に。
- **共有姿（インスタンス間の姿同期）**: データ導入の裏口になるため導入しない（3 で明記に留める）。
- **シナリオの本体構文への追加**: 本体文法の不変性を優先し別ファイルに隔離。
- **同名 `@S` の LIFO 規則の一意制約化**: 今回のスコープ外として見送り。

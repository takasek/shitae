# 検討を引き継ぐ

操作の記録だけでは、設計上の問いや期待は伝わりません。渡す人が操作前に期待と不変条件を書き、操作後に到達点と未確認範囲を追記します。ログから期待や意図を推測して自動生成したものとして扱わず、設計者が内容を確かめてください。

## コピーして記入する形式

空欄を残す代わりに「なし」「未確認」「未添付」と理由を書きます。通常の操作、状態の手動試験、結果途中からの分岐は別の経路として記録します。

```text
問い：何を再確認し、何を判断したいか
開始状態：画面、残っている作業、共有状態、通知、そこまでの操作
変更点：比較元と今回の定義の差分
期待する結果：操作・分岐と、その後に見える画面や状態
不変条件：操作を通じて維持する状態、起きてはいけない変化

資料と版：
- HTML：ファイル名、対応するモデル版
- 操作の再生ファイル：ファイル名、対応するHTML、保存時の到達点
- 処理系：生成に使ったcommit SHA（shitae-revision.txt）
- 定義：モデル版、入口ファイル、import一式の相対配置
- 設定：隣接するsimconfig.jsonの有無とファイル名
- 検討手順：書き出した手順または下記の短い操作列

経路ごとの確認：
- 種別：通常経路／状態の手動試験／結果途中からの分岐
- 開始方法：新しく始める／対応するHTMLに再生ファイルを読み込む
- 操作と選ぶ分岐：
- 結果途中から分岐した理由：該当なし、または操作・結果番号と理由
- 到達点と実際の結果：
- 判定：期待と不変条件の各項目を合格／不合格／未確認で記す
- 未確認範囲：

対象外：今回判断しない仕様や実装
```

## 記入例：取消と通知が予約状態を変えないか

[予約入門の段階5](TUTORIAL.md#5-通知と共有状態を別に残す)を使う記入例です。以下のファイル名は配布物の命名例で、このページには HTML や再生ファイルを添付していません。実際に渡すときは資料を用意し、版と結果を埋めてください。この例自体は実行済みの引継ぎ記録ではありません。

**問い**：受取で取り消したときに予約は未予約のままか。確定後に通知を閉じても予約済は残るか。

**開始状態**：新しく始めた「起動」。予約は未予約、通知なし。まだ一覧や確認の作業を開いていない。

**変更点**：比較元は入門の段階4。今回は段階5の定義へ置き換え、予約の共有状態と、成功時の予約済への変更・通知表示を加えた。比較は各版を新しく始めて行う。

**期待と不変条件**：取消では詳細へ戻り、予約は未予約・通知なしを維持する。成功では詳細へ戻り、予約済と通知が残る。その後の通知を外す操作は予約状態や画面を変えない。

**資料と版**：

| 資料 | この例での対応付けと、配布時に埋める値 |
|---|---|
| HTML | `booking-v5.html`：段階5の `booking.shitae` から生成 |
| 再生ファイル | `cancel-v5.scenario.json`：経路Aの取消後。`notice-v5.scenario.json`：経路Bの通知を外した後。いずれも上のHTMLで保存する |
| 処理系 | `shitae-revision.txt`：生成したcheckoutの完全なcommit SHAを記入（この例では未指定） |
| 定義 | `v5/booking.shitae`：段階5の全文を保存した入口。importなし。比較元は `v4/booking.shitae` に段階4の全文を保存 |
| 設定 | 両版とも隣接するsimconfig.jsonなし |
| 短い検討手順 | 下の経路A・B。比較元の段階4では取消の確認だけを同じ順で試す |

両経路とも新しく始め、「始める → 詳細を開く → 読込結果を試す → 成功 → 予約する → 受取を選ぶ」まで進めます。ここでは受取にいて、予約は未予約、通知なしです。

| 経路・種別 | 続ける操作 | 合格とする到達点 | 実際の結果・判定 |
|---|---|---|---|
| A：通常経路 | 取り消す | 詳細へ戻る。確認・受取の作業が閉じる。予約は未予約、通知なし | 未確認 |
| B：通常経路 | 確定結果を試す → 成功 | 詳細へ戻る。確認・受取の作業が閉じる。予約済、通知あり | 未確認 |
| Bの続き：通常経路 | 通知を外す → 予約一覧へ | 通知なし、予約済。予約一覧へ移るまで詳細に留まり、予約一覧でも予約済を確認できる | 未確認 |

**途中から分岐した理由**：A・Bとも該当なし。状態の手動試験も使わない。追加で使った場合は通常経路とは別行にし、操作・結果番号と理由を記す（[READMEの共有案内](../README.md#共有する)）。結果途中から作った状態へ実際の利用者が到達できるとは限らないため、その状態での確認だけで通常経路を合格にしない。

**対象外と未確認範囲**：実際の予約処理・在庫・通信・永続保存・書籍IDごとの管理は対象外。失敗分岐、手動試験、結果途中からの分岐、ブラウザを変えた確認は未確認。上表も記入例のため全項目未確認で、実施者が観測結果を記入するまで合格とはしない。

## 同版で再生する／修正版を試し直す

**同版の厳密再生**では、保存時と対応する HTML に操作の再生ファイルを読み込みます。CLI では対応する元モデルの入口名・全 import 先・全 source bytes と処理系の一致が必要です。編集・再生成する人にも元モデル一式と設定を渡します。HTMLに含まれる定義の内容から元ソースの bytes を復元できるとは考えず、元ファイルを保管してください。読込成功は記録との照合成功であり、設計上の期待に合格したことは別途確認します。[再生の使い方](design/session-usage.md#シナリオの保存と別processでの再生)を参照してください。

**修正版の試し直し**では、新しい HTML を生成して初期状態から始め、旧版の[検討手順](design/session-provenance.md)を参照して操作と分岐を人が選び直します。旧版の再生ファイルを修正版へ読み込めるとは想定せず、期待・不変条件と比較した結果を新しい記録に保存します。旧版と修正版の資料は分けて対応付けてください。

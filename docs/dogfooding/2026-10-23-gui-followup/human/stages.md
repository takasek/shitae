# 人向け受取評価の実施段階

## 状態

見学予約v2のHTMLと対応する9 dispatchのscenarioを、新しいGUIに読み込んだ。AIは読込だけを補助し、人の回答と次の操作・保存は待機中。元モデルや作者のreport・補助scriptは追加提示していない。利用者は前段の評価概要を読んでいるため、完全な初見とはしない。

## 段階と判定

| 段階 | 提示物と課題 | 現在 |
| --- | --- | --- |
| 1 読取 | HTML・scenarioだけから経緯、現在の状態、選んだ条件を説明する。分からない点もそのまま記録 | 質問提示済み・回答待ち |
| 2 継続 | 人が次に確かめたい操作を一つ実行し、GUIで再保存する。回収した実ファイルで選択と再生を確認 | 実行報告・保存物待ち |
| 3 編集・再検討 | 1・2の後に元モデル一式・版・必要な設定を提示し、再生成、一箇所の要件変更、旧記録拒否、新規記録を人が判断する | 未開始 |
| 4 途中分岐の説明 | 作者の答えを先に示さず別の分岐記録を読んでもらい、その後に分岐理由を添えた資料を提示する | 未開始。単純な見学予約の記録を途中分岐の効果確認へ流用しない |
| CLI負担 | cli-task.md。人が端末でhandleを再取得・転記する手間を確認 | 準備のみ・未実施 |

人の発言を根拠に、理解できた範囲・迷い・追加質問を記録する。AIが代行して達成済みにしない。同じ人への段階的な説明の前後だけで、一般の人への改善効果を断定しない。

人向け評価待ちのブラウザーをAIが操作して入力・履歴を変えない。評価中はlocalhost配信を保持する。終了時は配信停止を確認し、実際の状態を報告する。

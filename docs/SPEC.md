# shitae — UI ラフスケッチ記述言語

> 下絵（したえ）。完成画の前の下描き。Figma や実装に入る前の、
> 画面・表示要素・インタラクション・遷移を、テキストで速く描いて AI と揉むための言語。

uiflow の精神（「見るもの／すること」を繋ぐ）を継ぎつつ、
画面と部品を **component** に統一し、AI との往復に最適化して再設計した。

---

## 設計原則

1. **ラフであることが機能**。穴・未定・自然文を許す。厳密さが要る段階に来たら、それは shitae の仕事ではない（状態機械なら XState 等に「降りる」）。
2. **専用記法を増やさない**。表現できないものは自然文で書く。未定も状態も注記も、自然文に開く。
3. **構造記号は構造のためだけ**。キーワードは遷移語のみ。見出し語を持たず多言語中立。
4. **画面と部品を区別しない**。すべて component。トップレベルで遷移グラフに乗れば「画面」に見えるだけ（SwiftUI の View と同じ）。
5. **インデントは意味を持たない**。構造はすべて明示的な記号（`#` `##` `---` `:` `*` `{}` `.` `->` `;` `[]` `@` `::` `//`）で表す。
6. **状態は条件式ではなく「姿」で表す**。「いつ何ができるか」は、変数とガードではなく、目に見えるバリエーション（姿）の列挙で表現する。

---

## 二層モデル

shitae は 2 つの階層でできている。

- **component**（`#`）— 画面でも部品でもある、設計の単位。
- **バリエーション＝姿**（`##`）— 1 つの component が取りうる見た目の状態。読込中／表示中、など。
  姿は省略でき、姿を書かない component は「単一の姿だけを持つ」とみなす（＝従来の画面）。

各姿は **要素節**（何が見えるか）と、`---` を挟んだ **インタラクション節**（何ができるか）からなる。

`##`（最初の姿）より**前**に書いた要素・インタラクションは、**全姿に共通**する部分になる。各姿は「共通部分 ＋ その姿固有の部分」として描かれる（共通が先、固有が後）。共通部分は省略できる。`##` を 1 つも書かなければ、その component は「単一の姿だけを持つ」（＝従来の画面）。

```
# component名
（共通要素節）                 ← ## より前。全姿に共通。省略可
---
（共通インタラクション節）      ← 全姿に共通。省略可
## 姿1                        ← バリエーション（省略可。無ければ単一の姿）
（固有要素節）
---
（固有インタラクション節）
## 姿2
（固有要素節）
---
（固有インタラクション節）
```

例：`x` の姿 ＝ 共通 ＋ x 固有、`y` の姿 ＝ 共通 ＋ y 固有。

遷移は「component の間」も「同一 component の姿の間」も同じ遷移語で書く（行き先で区別しない）。遷移語はコアが 4 つ（`push`/`back`/`goto`/`exit`）、`present`/`dismiss` はその糖衣。一覧は「遷移語」を参照。

## 記号一覧（これで全部）

| 記号 | 役割 |
|------|------|
| `#` 名前 | component 定義（見出し。語彙を持たない。名前はユーザー命名） |
| `##` 名前 | バリエーション（姿）定義 |
| `---` | 要素節とインタラクション節の区切り（語彙ゼロ・多言語中立） |
| 名前 | component 参照。すべて対等（特権的な組み込み component はない）。定義があれば自作、なければ未定義。名前は自由 |
| `*` | 集合（前置。要素行の先頭、alias の前）。`*サムネイル` / `*手札: カード`。複数あるという宣言。参照すると 1 インスタンスを指す |
| `名前: 実体` | alias（`左: 右` ＝ 名前: 実体）。要素や inline に呼び名を与え、参照・命名に使う |
| `{ ... }` | inline component（その場限りの定義。中身は `;` か改行で区切る） |
| `.` | 要素参照（`alias.要素alias` / `名前.要素alias`）。1 段まで。他の component の内部要素も外から参照でき、文脈ごとに挙動を差せる |
| `##` | バリエーション参照（`component##姿` / 同一 component 内は `##姿`）。遷移先に姿を指定する時。定義 `## 姿` と数が揃う |
| `->` | 行動と結果の境界 |
| `;` | 結果列の区切り（改行でも可） |
| `[ ... ]` | 条件ラベル（評価しない注記。分岐の目印） |
| `@名前` | セッション（開始して破棄する期間の名前）。`push(X, @名前)` / `present(X, @名前)` で開始し、`exit(@名前)` / `dismiss(@名前)` で破棄 |
| `::` | 名前空間区切り（`モジュール::component`）。import した別ファイルの component を参照 |
| `// 自然文` | コメント（行末・行頭どちらでも）。`#` と衝突しないので component 定義と紛れない |

**予約語**：
- 遷移語（コア）：`push` `back` `goto` `exit`
- 遷移語（糖衣）：`present`（= `push` ＋無名セッション） `dismiss`（= `exit` 無名セッション）
- 構造キーワード（モジュール化）：`import` `as`

これ以外のキーワードは持たない。

`.`（要素）と `##`（姿）は軸が違う：`.` は component の中身、`##` は component の姿。

ある component に置いた別 component（部品）の内部要素を、外側から `インスタンス.要素alias` で参照できる（例：`自分.フォロー -> push(編集)`）。これにより、同じ部品を文脈ごとに違う挙動で使える（自分のページなら編集へ、他人のページならフォロー）。部品定義側に書いた挙動はその部品単体でのデフォルト、外側から書いた参照はその文脈での上書き。

参照は **alias 名（または component 名）** で引く。要素を参照したいときは、その要素に alias を付けておく（同名の要素が複数あり得るため）。同名の要素 alias が複数の姿にまたがって存在しても**曖昧にはならない**。それは「姿に依らず存在する共通の操作」を意味し、挙動はどの姿でも共通。したがって姿を明示する合成記法（`component##姿.要素`）は不要で、用意しない。

## 文法（EBNF 風）

```ebnf
document        = { import } , { component } ;

import          = "import" , module-name , "as" , alias-name ;
module-name     = (* 同ディレクトリの .shitae ファイル名（拡張子省略）またはパス *) ;

component       = header , common-body , { variation } ;
header          = "#" , name ;                       (* セッションはここでは打たない（遷移時に打つ） *)

common-body     = single-body ;                      (* ## より前。全姿に共通。空でもよい *)
variation       = "##" , name , single-body ;        (* 姿固有。variation が 0 個なら単一の姿 *)
single-body     = element-section , [ "---" , interaction-section ] ;

element-section = { element-line } ;
element-line    = [ "*" ] , [ alias-name , ":" ] , ( ref | inline ) ;  (* * は行頭（alias の前） *)
alias-name      = name ;
ref             = name ;                             (* すべて対等。自作/未定義を問わない *)
inline          = "{" , inline-body , "}" ;          (* 要素のみ。姿(##)やインタラクション(---)は持たない *)
inline-body     = element-line , { ( ";" | newline ) , element-line } ;

interaction-section = { interaction-line } ;
interaction-line    = action , "->" , result-list ;
action              = free-text , [ "(" , reference , ")" ] ;  (* 行動は自然文。対象を取るときだけ括弧。対象なしは括弧省略 *)
reference           = [ module-name , "::" ] , name , [ "." , name ] ; (* [モジュール::]component名 / alias.要素alias。1段 *)

result-list     = result , { ( ";" | newline ) , result } ;  (* (条件, 結果) の組の集合 *)
result          = [ "[" , label , "]" ] , ( transition | effect ) ;
label           = free-text ;                        (* 条件ラベル。評価しない注記 *)
(* 意味論: 行動 A(C) -> R は (条件, 結果) の組の集合。
   [ラベル] 付きの result は (そのラベル, 結果)、[ラベル] なしは (常に成立, 結果)。
   矢印 -> は 1 つだけ。分岐は -> の後に ; で複数の [条件] 結果を並べる。
   -> R -> R のように矢印を重ねるのは構文エラー。 *)
transition      = push-nav | present-nav | goto-nav | back-nav | exit-nav | dismiss-nav ;
(* 積む側：第2引数に任意のセッション @S。present は push の糖衣 *)
push-nav        = "push" , "(" , nav-target , [ "," , session ] , ")" ;
present-nav     = "present" , "(" , nav-target , [ "," , session ] , ")" ;
(* 置き換え：セッション不可（積まないので begin 地点を残せない） *)
goto-nav        = "goto" , "(" , nav-target , ")" ;
(* 戻る：画面方向。引数は常に component（セッションではない） *)
back-nav        = "back" , "(" , [ nav-target ] , ")" ;
(* セッション破棄：引数は常にセッション。dismiss は exit の糖衣 *)
exit-nav     = "exit" , "(" , session , ")" ;
dismiss-nav     = "dismiss" , "(" , [ session ] , ")" ;   (* 空なら直近の無名セッション *)
session         = "@" , session-name ;
nav-target      = [ module-name , "::" ] , name , [ "##" , name ]   (* [モジュール::]component[##姿] *)
                | "##" , name ;                                     (* 同一 component 内の姿 *)
effect          = free-text ;                        (* 副作用。reload 等もこれ。予約語なし *)

comment         = "//" , free-text ;                 (* 行頭・行末どちらでも *)
name            = (* 任意の識別子。日本語可 *) ;
free-text       = (* 任意の自然文。行コメント // の手前まで。
                     結果列の中では区切り ; と次の result まで。
                     行動内（括弧前）では -> の手前まで *) ;
```

アンカーを打てるのは進む・置き換える側（`push` / `goto` / `present`）。`back` / `dismiss` は参照側（`@名前` で戻り先を指す）。

## 操作は姿に属する（条件式を持たない理由）

インタラクションは、それが書かれた**姿（バリエーション）の中でだけ有効**。
「ある状況でだけ可能な操作」は、ガード条件式ではなく、その操作を持つ姿を用意することで表す。

```
# プロフィール
## 未フォロー
フォロー
---
タップ(フォロー) -> フォローする ; goto(##フォロー済)

## フォロー済
フォロー解除
---
タップ(フォロー解除) -> 解除する ; goto(##未フォロー)
```

未フォローの姿には「フォロー」操作があり、フォロー済の姿には無い（代わりに「フォロー解除」がある）。
「いつ何ができるか」が、`if 状態 == X then ...` ではなく、姿ごとの操作の有無として現れる。
shitae は条件を**評価しない**。姿に居る、ただそれだけ。これがガードの沼に落ちずに状態を表す流儀。

**共通部分と姿固有部分で同じ行動が衝突したとき**（共通に `タップ(戻る) -> back()`、ある姿にも `タップ(戻る) -> goto(別)` がある等）、shitae はどちらが優先かを**決めない**。両方を有効な候補として残し、解釈は読み手（人間・AI）に委ねる。これは内側／外側どちらが勝つかを確定させない CSS セレクタの割り切りに近い。重複は「書き手がまだ整理していない」というシグナルであって、エラーではない。図示ツールやリンタは**警告**してよいが、エラーにはしない。

## 遷移語

コアは **`push` / `back` / `goto` / `exit`** の 4 語。**`present` / `dismiss`** はその糖衣（後述）。

| 語 | 何をする | 後で戻れる |
|----|----------|------------|
| `push(X)` / `push(X, @S)` | X へ進む（積む。back で戻れる）。`@S` で「@S セッション」を開始（back の壁なし） | ○ |
| `back()` / `back(X)` | 直前へ／component X まで戻る（画面スタックを戻る） | — |
| `goto(X)` | 現在を X に置き換える（積まない） | ✗ |
| `exit(@S)` | @S セッションを破棄（begin した地点へ戻る） | — |
| `present(X)` / `present(X, @S)` | モードに入る（モーダル・ログイン後フロー等）。back の壁あり＋セッション。`push` の糖衣 | △ |
| `dismiss()` / `dismiss(@S)` | 直近のモーダルを閉じる／@S を破棄。`exit` の糖衣 | — |

`back` は **画面スタックを戻る**（引数は常に component）。`exit` は **セッションを終える**（引数は常にセッション `@S`）。役割が違うので予約語を分ける——`back(X)` の X は必ず画面、`exit(@S)` の @S は必ずセッション。`@` で見分けるのではなく、語で意味が確定する。

### push / goto と行き先

- **`goto`** は「積まない置き換え（ジャンプ）」。対象は同一 component の姿でも別 component でもよい。
  - `goto(##表示)` … 同一 component の別の姿へ（姿替え。`##` で姿を明示、component 名は省略）
  - `goto(ホーム)` … 別 component へ、戻れない置き換え（ログイン→ホーム等）
- `goto` は**セッションを開始できない**（`goto(X, @S)` は不可）。セッションは「begin した地点に戻る」前提だが、goto は積まずに begin 地点を消すため、畳む基点になれない。
- 行き先は `component` / `component##姿` / `モジュール::component` / `##姿`（同一 component 内の姿）。

### 姿の参照は必ず `##`

姿（バリエーション）を参照するときは常に **`##姿`** と書く。定義の `## 表示` と参照の `##表示` で `#` の数が揃う。

- `記事詳細##表示` … 別 component の姿（component ＋ `##` 姿）
- `##表示` … 同一 component 内の姿（component 名を省略）

同一 component 内では component 名を省略できるが、**姿名を component 名のように裸で書いてはいけない**。`goto(表示)` は「表示という component へ」の意味になり、姿替えにならない。姿替えは `goto(##表示)`。

### セッション（`@S`）

セッション `@S` は **「開始して、まとめて破棄する、ひとまとまりの期間」**。ログインセッション、チェックアウトセッション、モーダルを開いている間、など。`push(X, @S)` / `present(X, @S)` で**開始**し（その遷移が begin）、`exit(@S)` / `dismiss(@S)` で**破棄**する（begin した地点へ戻る）。

```
タップ(開始) -> push(確認, @checkout)        // @checkout セッション開始（確認へ進む）
タップ(確定) -> 注文する ; exit(@checkout)  // @checkout を破棄して begin 地点へ
```

- セッションを開始できるのは積む側（`push` / `present`）のみ。`goto` は不可、`back` は画面方向なので無関係。
- **セッションは遷移に紐つく**。`push(X, @S)` を実行したその push が begin。同じ画面を別の場所で push すれば別のセッションになる。component や姿そのものにセッション名が固定されるわけではない。

#### セッションと「back の壁」は直交

「まとめて破棄できる範囲（セッション）」と「モード内から外へ通常の `back` で出られるか（back の壁）」は**別の軸**。

| | back の壁なし | back の壁あり |
|---|---|---|
| **セッションあり** | 閲覧フロー（`push(X, @S)`）：経路を `back` で 1 つずつ遡れる＋ `exit(@S)` で一気に戻れる | モーダル／モード（`present(X, @S)`）：内側で `back` しても外へ出ず、`dismiss`/`exit` で一括 |

- **`push(X, @S)`** … back の壁**なし**＋セッション。例：記事 → 関連記事 → さらに関連、と深く潜り、各段は `back` で遡れるが、「ホームへ」で `exit(@S)` すれば何段潜っていても一気に戻れる。
- **`present(X, @S)`** … back の壁**あり**＋セッション。モード（モーダル）に入り、内側の `back` は外に出ない。`dismiss`（無名）／`exit(@S)`（名前付き）で出る。

`present` が「壁あり＋セッション」を一語で担う糖衣。`push(X, @S)` は「壁なし＋セッション」。壁を独立に指定する記法は持たない（頻出するこの 2 パターンに名前を与えれば足りる）。

### セッションスタックと LIFO

処理系は内部的に**セッションスタック**を持つ（`push`/`present` で積み、`exit`/`dismiss` で破棄）。これは意味を与えるための内部モデルで、**ユーザーがスタックを直接操作する記法はない**。

`exit(@S)` / `dismiss(@S)` は、**スタックを新しい方から走査し、最初に見つかった `@S` を破棄してその begin 地点へ戻る**。

- `@S` が一意なら、間に積まれたものを越えてそこまで一気に破棄（範囲破棄）。
- 同名 `@S` が複数あれば、直近の `@S` まで（LIFO で 1 段）。

1 つのルール（「新しい方から最初の @S まで」）で両方を説明できる。LIFO が基底で、一意セッションはその特殊ケース。

### present / dismiss は糖衣

`present` / `dismiss` は **無名セッションを使う `push` / `exit` の糖衣**。

- `present(X)` ≡ `push(X, @無名)` … モーダル（無名セッション）を開始して X を開く。「これはひとまとまりで `dismiss` でまとめて閉じる対象」という**意図**を読み手に伝える。
- `dismiss()` ≡ `exit(@無名)` … 直近に開いた無名セッション（モーダル）を破棄。多段 `present` は無名セッションが積み重なり、`dismiss()` は **LIFO で直近を 1 つ**破棄。
- 複数のモーダルを跨いで破棄したい／区別したいときは `present(X, @S)` と**名前を付け**、`dismiss(@S)` で「@S まで」破棄する。

`present` は専用セッション名を予約しない。「セッション省略 ＝ 無名、`dismiss` は直近対応」というだけ。

**`present` は「モードに入る」遷移全般に使う**。画面上の見せ方（全画面・シート・ダイアログ）は問わない。本質は「独立した文脈（モード）に入り、戻るときはそのモードごと終える」こと。モーダルだけでなく、たとえば**ログイン後フロー**もこれで表す：

```
# ログイン
ログインボタン
---
タップ(ログインボタン) -> present(ホーム, @loggedIn)   // ログイン後モードに入る（ログインには戻れない＝back の壁）

# 設定
アカウント削除
---
タップ(アカウント削除) -> present(削除確認)             // 確認モーダル

# 削除確認
削除実行
---
タップ(削除実行) -> アカウントを削除する ; exit(@loggedIn)   // ログイン後モードを抜ける＝ログインへ
```

`present(ホーム, @loggedIn)` は「ホームをモーダル提示する」のではなく「ログイン後というモードに入る」。ログインには通常の `back` で戻れない（back の壁）。ログアウト／アカウント削除は `exit(@loggedIn)` でそのモードを抜け、begin 地点（ログイン）へ戻る。`present`/`dismiss` という語は UI の見せ方を連想させるが、ここでは「モードの出入り」という本質で使っている。

### セッションのねじれ

`push` で積んだものを `dismiss` で閉じる、`present` したものを `back` で戻る、といった**ねじれ**た書き方は、shitae では**エラーにしない**。静的に検出しづらく、止めると作図の妨げになるため。ただしこのまま実装に進むと画面遷移の設計問題になりうるので、処理系は**実行時に警告**してよい。

## 行動（インタラクションの左辺）

インタラクションの左辺は **行動**。行動は**自然文で何でもよい**（タップ／長押し／引っ張って更新／3秒長押し…）。評価されない注記であり、同じ対象に複数の異なる行動を書ける。

対象を取るときだけ括弧に参照を入れる。対象を限定しない行動（画面全体のスワイプ、対象が自明な更新など）は括弧を省略してよい。

```
タップ(設定) -> present(設定)
長押し(設定) -> present(クイック設定)            // 同じ対象に別の行動
タップ(保存) -> 設定が保存される ; dismiss()      // 副作用と遷移を併記
更新 -> リストが更新される                        // 対象なし・遷移なし。括弧省略
```

左辺 `行動(対象)` と、右辺の遷移 `遷移語(対象)` は同じ「語(対象)」の形で対称。左辺の語は自由な自然文、右辺の遷移語はコア 4 つ（`push`/`back`/`goto`/`exit`）＋糖衣（`present`/`dismiss`）に限られる。右辺にはこのほか副作用（自然文）も書け、`;` で並べられる。

> 注意：右辺に遷移語がなければ**副作用**（自然文）と解釈される。`保存 -> 完了` の `完了` は「完了する」という副作用であって、画面遷移ではない。`完了` という画面へ遷移させたいなら `push(完了)` と書く。遷移のつもりで遷移語を書き忘れると、黙って副作用扱いになる（ラフさの代償）。図示ツールは、未定義 component への遷移は描けても、遷移語なしの自然文は edge にしない。

## component に特権はない

`card` `text` `button` `field` のような**組み込み component は持たない**。すべての名前は対等で、定義があれば自作 component、なければ未定義 component（ラフに置いただけ）。`button` と書いてもよいが、それは「button という名の component を置いた」だけで、押せる・見た目がボタン、といった特別な意味は持たない（押せるかどうかは行動を書いたかで決まる）。

アラート・トースト・モーダルのような汎用部品も、必要になったらその場で `#アラート` のように明示的に定義して使う。言語はメカニズム（component 定義と遷移）だけを提供し、どんな部品があるかという語彙は書き手が決める。

## inline component とグルーピング

`{ ... }` で、その場限りの component を定義できる（**要素のみ**。姿 `##` やインタラクション `---` は持たない）。alias を付ければ、入れ物と中身の両方に名前が付く。

```
フィード: {
  *サムネイル
}
---
スクロール(フィード) -> 続きを読み込む          // 入れ物（集合）への操作
タップ(フィード.サムネイル) -> push(記事詳細)     // 中の要素への操作
```

「集合と入れ物に別の名前を付けたい」（フィードの中にサムネイル）という要求は、これで満たせる。`*` を付ける名前で集合性が決まる：`*フィード: { サムネイル }` なら「フィードが複数」、`フィード: { *サムネイル }` なら「単数のフィード、中にサムネイルの集合」。`in` のような専用記法は導入しない。inline が物足りなくなったら（姿やインタラクションを持たせたくなったら）、名前付き `#` component に昇格させる。inline は「要素をまとめる軽い箱」、挙動は外側の `---` から参照して書く。

## モジュール化（名前空間）

規模が大きくなったら、**ファイル＝モジュール＝名前空間**として分割する。見出しレベル（`#`/`##`）に名前空間を積まない（レベルのインフレを避ける）。1 ファイル内の文法は分割しても変わらない。

```
import auth as auth          // auth.shitae を読み込む

# ホーム
---
タップ(ログイン) -> push(auth::ログイン画面)     // 別モジュールの component を :: で参照
```

- `import モジュール名 as 別名` で別ファイルを読み込み、`別名::component` で参照する。モジュール名は同ディレクトリの `.shitae` ファイル名（拡張子省略）。サブディレクトリはパスで書く。
- 区切りは `::`（`.` は要素参照、`#` は姿参照と用途が分かれているため別記号）。
- `import` と `as` は構造キーワード（遷移語とは別カテゴリ）。

## 集合（`*`）

- `*` は要素行の**先頭**（alias があればその前）に置く。「この行が宣言する参照単位が複数ある」という意味。
  - `*サムネイル` … 複数のサムネイル
  - `*手札: カード` … 複数のカード、各々を「手札」と呼ぶ（`手札` で 1 枚を指す）
- `*` を先頭固定にすることで、alias や inline と組んでも掛かる先が一意になる（`*フィード: { *サムネイル }` ＝ 複数のフィード、各々の中に複数のサムネイル）。
- インタラクションで参照したときは **1 インスタンス**を指す（`タップ(サムネイル) -> push(詳細)` ＝ サムネイルを 1 つ選んだら詳細へ）。
- 集合全体への操作が要るなら、inline で入れ物に名前を付けて参照する（`*サムネイル` を `フィード: { *サムネイル }` で囲み `スクロール(フィード)`）。「inline component とグルーピング」を参照。

## 未定・分岐

- **未定**は専用記法を持たない。`present(まだ決めてない画面)` `削除 -> 行き先は未定` のように自然文で書く。
- **分岐**は条件ラベル `[...]` を結果に添えて、**1 つの `->` の後に `;` で並べる**。条件は評価されない注記：

```
タップ(保存) -> [成功] goto(詳細) ; [失敗] エラーを表示する
```

**矢印 `->` は 1 行に 1 つだけ**。分岐を `-> R -> R` のように矢印を重ねて書くのは構文エラー。複数の結果は必ず `;`（または改行）で区切る：

```
// 誤り（矢印が 2 つ）
タップ(保存) -> [成功] goto(詳細)
            -> [失敗] エラーを表示する

// 正しい（-> は 1 つ、; で並べる）
タップ(保存) -> [成功] goto(詳細) ; [失敗] エラーを表示する
```

**意味論**：結果列は **(条件, 結果) の組の集合**。`[ラベル]` 付きは `(そのラベル, 結果)`、`[ラベル]` なしは `(常に成立, 結果)`。形式的には、行動 `A(C) -> R` は `(exists(C), R)` の組とみなせる（条件 C が満たされたとき結果 R）。shitae は条件を評価しないが、この形式化により処理系・図示ツールは「どの条件でどの結果か」を構造として扱える。

> 注意：遷移は必ず遷移語（`push` 等）で書く。`タップ(保存) -> 完了` のように遷移語なしで component 名を書くと、それは**遷移ではなく副作用（自然文）**として扱われる（「完了する」という意味になり、`完了` 画面への遷移にはならない）。画面へ遷移させたいなら `push(完了)` と書く。ラフさの代償として、この取り違えは処理系では検出されない（後でグラフ化や実装に落とす段で気づく）。

## 扱わないもの（意図的に持たない）

- 状態の条件式・ガード・並行状態（姿で表す。式は評価しない）→ 状態機械（XState 等）の領分
- データ／コンテキスト（変数、フォーム値の保持）、component への引数・props → 実装の関心
- 履歴スタックのデータ構造、戻り先の自動解決
- レイアウト・見た目・寸法 → Figma 等の領分
- component の型・プロパティ定義
- atom / molecule のような粒度（実装・デザインシステムの語彙）

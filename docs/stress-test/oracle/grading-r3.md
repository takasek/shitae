## 乖離の分析（確信度「高」× 不一致 = 読者期待と実装の衝突）

### S2 — switch resume 経路の `X##v` 共有書換が SPEC 未転記

ADR-0011 は「明示 `##v` の共有 variant 書き換えは switch の **resume 経路にも及ぶ**（2026-07-13 設計者確定）」を持つが、SPEC 本文は switch 節「このとき X は無視される」と singleton 節「`X##v` 指定は共有状態の書き換え」を並記するのみで、resume 時の優先関係を明示しない。被験者は両節を正しく読んだ上で「X 無視」を優先し誤答した——**SPEC の字義だけでは設計者確定と逆の解釈に必然的に到達する**。SPEC singleton 節（または switch 節）への 1 文追記が要る。

### S5 — singleton のモジュール境界（R3-4 の読者期待側の証拠）

被験者は「`::` で名前空間が完全に分離される原則から、A と B の同名クーポンが状態を共有する根拠は無い」と推論し B::クーポン は initial（##未受取）で開くと予測。実装は component 素名キーのため A ローカルの `push(クーポン##通常)` が共有レジストリを汚染し、B::クーポン が**自分に存在しない variant ##通常**で開く。読者期待（名前空間分離）と実装（名前キー合流）が正面衝突——spec-review R3-4 と合わせ、設計判断（document 境界の規定）+ 実装修正の両方が要る。

# smarthome-r4 採点（被験者: sonnet・SPEC のみ参照・モジュール分割必須）

正解器: `cli check`（3 ファイルとも exit 0・無診断）+ 手動意味論照合 + parser 直呼び実測。

## ✅ 正しく書けたもの（r4 焦点構文がほぼ全部正解）

- **セキュリティバナー = singleton overlay + set**（要件 2）: `#! セキュリティバナー` を常時掲示し、第三の画面（モード切替）から `set` で書換 — 「掲示中 singleton への set の即時反映」の正攻法
- **set + show(X) の分解形を自発選択**（判断 4・確信度中）: 起動時の初期化を `show(X##在宅)` 一発でなく `set(セキュリティバナー##在宅) ; show(セキュリティバナー)` に分けた。理由申告「SPEC は singleton への明示 variant 付き show を巻き戻しと述べており、意図を明確にするため」——**ticketing-r3 G2 の罠を SPEC の記述だけで自力回避**。さらに「explicit-variant show が警告の対象になるのか判断が割れた」と、存在しない警告を予期する申告あり（G2 lint 化判断の直接材料）
- **variant 分割 + set の C2 誘導**（要件 5）: gate の「対象=条件源」制約を正しく読み、ホームを `#!` 化して `##通常`/`##就寝中` を分割、モード切替から set で追随 — ADR-0016 C2 で書いた誘導文がそのまま機能
- **`devices::` 明示修飾の set**（要件 3）: doc common の外部事象 set を全て module 修飾つきで書き、無修飾解決の罠（オラクル Q2 で被験者が踏んだ座標）を回避。しかも「この doc common が有効なのはアクティブ画面が本ファイル定義の時だけ」とスコープ限定を正しく認識・注記
- **`exit(@wizard) ; push(オートメーション一覧)` の出口固定慣用句**（要件 4）: キャンセル・完了とも。複数入口（一覧・デバイス詳細）を意図的に用意して慣用句の効きを確認する構成
- ウィザードのステップ遷移を goto(##) で書きフレームを増やさない・@wizard の begin は入口 1 回ずつ（R005 誤読なし——fitness の haiku と対照的）

## 発見（申告 → 裏取り実測）

### S1: 要素行はモジュール修飾を書けない — しかも parser が黙って壊れた名前にする【申告+実測】

被験者は EBNF 精読で「`::` が書けるのは行動対象と nav-target だけ、element-line の ref は裸 name のみ」を発見し、「ローカル同名 placeholder 要素 + 遷移先だけ `devices::` 修飾」の回避行動を踏んだ。裏取り実測: 要素行に `mod::部品` と書くと parser は **`{kind:"ref", name:":部品"}` を無診断で受理**（`mod` 消失・`:` 残留の壊れた名前）。被験者要望: 要素行でも `::` を許すか、少なくとも「他モジュール component と同名のローカル未定義要素」の lint。

### S2: 「全モジュール共通の外部事象」を 1 箇所に書けない【申告】

doc common はアクティブ画面のファイル単位なので、`main.shitae` に置いた「通信が途絶える」イベントは devices/automation の画面を見ている間は存在しない。要件の字面（「デバイス詳細を開いていなくても」）は満たすが、「本当にどの画面でも起こる外部事象」はモジュールごとに複製するしかない。SPEC はこのギャップに言及なし。

### S3: variant の直交 2 軸が書けない【申告・既定路線と緊張】

オンライン/オフライン × 電源オン/オフ で組合せ爆発。今回は電源操作を自然文副作用に丸めて逃げた。並行状態は「扱わないもの」の領分だが、実書きでの摩擦として記録。

### S4: キー付き singleton が欲しい【申告・見送り想定】

「デバイスごとに 1 つずつだが種類は増減する」を 1 定義で書けず component ×3 複製。props 不保持の直接の帰結（確信度高で正しく複製を選択）だが、台数が増えるとラフの速さが失われるという申告。

### S5: 「元の値を覚えて戻す」不可【申告・想定内】

おやすみ解除の行き先を在宅固定に。データ不保持の明記済み制約で、被験者も想定内と自己申告。

## 総評

sonnet は r4 焦点構文（set・singleton・module・session）で誤りゼロ。乖離はすべて「言語に無いもの」への申告として現れ、回避行動の質も高い（G2 回避・Q2 罠回避・R005 誤読なし）。r3→r4 で SPEC に足した誘導文（C2 の variant 分割 + set・出口固定慣用句・show の巻き戻し注意）が全て読者に届いた実証。

# photosns-r2 採点（被験者: haiku、SPEC のみ — モデル勾配測定枠）

## CLI 実測

- `check`: **E015 ×1**（`投稿: { …; 投稿者: { … } }` の inline 入れ子）。notes には「inline の入れ子は 1 段が上限」を正しく書き写している — **規則の知識と適用が乖離**（ルールを読めても大きな構造を書く時に忘れる。lint があるから救われた実例）
- ほか診断ゼロ。ただし下記の無音受理 3 系統が check をすり抜けた

## 無音受理（probe が踏んだ処理系/SPEC の穴）

1. `> back() -> back()`（行動側に `back()`）— **空括弧の対象参照が name="" で AST に乗る**。診断なし。被験者はシステム戻るジェスチャを表現したかった（C 系: 戻るジェスチャの語彙需要 + E 系: 空参照の検査欠落）
2. 要素行 `ストーリーサムネイル?` — **要素行に置いた `?` が名前に混入**（要素名 `ストーリーサムネイル?`）。gate 参照 `タップ(ストーリーサムネイル?)` は `?` を剥ぐので**永遠に一致しない別名**になる。無音（show(*X) と同族の「記号が name に食われる」系）
3. inline 要素 `[いいね通知] 対象投稿のサムネイル` — **要素行の condition label が名前に混入**。被験者は「条件付き要素」を書きたかった（C 系需要: variant を分けるほどでもない要素の出し分け）

## 意味論の誤適用（確信度 高で書いた誤り — 最も危険な種類）

- `> タップ(タブバー.フィード) -> switch(フィード, @tabFeed) ; goto(##通常)` — 意図は「ホームのバッジを消してからフィードへ」。B1 逐次意味論では goto は**切替後のフィード**の variant を `通常` に書き換える（フィードに ##通常 は無い）。notes は「タブ切替と並行して実行可能」と誤解を明記。正書は `goto(##通常) ; switch(…)`。**B1 の 1 文はあるが、切替系 verb の後の goto が「新しいアクティブフレーム」に効くことの worked example が無い**
- 未定義 variant への goto（`goto(##通常)` on フィード）は check も runtime も無音 — lint 候補

## 正答した点

- タブ慣用句・エントリ「ローンチ」component・present(@postCreation) の barrier + 段階 push + 途中 dismiss の複合 — SPEC の意図どおり
- フォロー前/済の variant 対 — SPEC 参照実装例の正しい転用
- document common の deep link・前方参照 — 正しい

## モデル勾配所見

haiku でもタブ・セッション・variant の基本は完走（round-1 と同傾向）。落ちたのは (a) 大きな inline 構造での規則適用、(b) 逐次意味論の演算順序、(c) 記法にない記号（`?`・`[label]`）を要素行へ外挿 — いずれも仕様側の誤読誘発点で、モデル能力の問題に還元できない部分が残る。

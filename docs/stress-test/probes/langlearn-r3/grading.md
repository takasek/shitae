## ❌ CLI が検出したエラー

### G1: 継続行の `>` 落とし（L39-42）

```
> タップ(選択肢) ->
    [正解] 正解の演出を行う ; 次の問題を出題する
```

SPEC の正準例（「未定・分岐」）は継続行にも `>` を付けるが、被験者はインデントだけで継続を表現した。帰結: `->` の後が空 → E003、`[正解]` 等の行が**要素行**扱い → W104 ×3。**W104 はまさにこの取り違えを拾う設計どおりに発火した**が、E003「空の result-list」は書き手（続く行が結果のつもり）には意味不明で、「継続行には行頭 `>` が要る」へ誘導する診断が無い。E003+W104 同時発火は `>` 落としの強いパターン — 診断メッセージのヒント改善候補（D）。

## 表現力ギャップ申告（C 候補。一次資料で妥当性確認済み）

### C-a: 非アクティブフレーム / 別 component の variant を遷移なしで書き換える手段が無い【最重要・両プローブ収束】

ハート自然回復（学習画面が非アクティブな間に起きる）は chaining すら使えず自然文コメントに諦め。被験者提案: (i) gate の対象を行動対象以外の任意参照に拡張、(ii) 遷移を伴わない variant 書換の専用 result 種別。**ticketing-r3（haiku）も「カート 0 件でミニカート非表示」で同じ壁**に当たり自然文放置 — 2 被験者が独立に同じ摩擦へ収束（最強シグナル）。なお singleton なら `show(X##v)` が遷移なし書換になるが、掲示という副作用が付く。

### C-b: gate は「対象自身の状態で対象自身への操作を制御する」ケース専用

「ハートの状態で**レッスン開始ボタン**を制御」は書けない（gate 対象 = 行動対象、member gate は対象自身の variant を見る）。被験者は「この非対称に気づくまでに時間がかかった」と申告し、gate を **1 箇所も使わずに完成**させた（回避行動）。SPEC の例（日付.選択可能?）が「対象=条件源」型のみである旨の明示、または条件源を分離する記法の議論が要る。

### C-c → D: document common / component common の要素行の意味論が本文に無い

streak バッジを doc common の要素行として全画面に載せる案を、「文法上は書けるが本文の説明・例がインタラクション一辺倒で、全 component の表示に乗るのか確信が持てない」ため見送った。EBNF は `document-common = single-body`（要素行を含む）を許すのに、本文は一度も要素行の帰結を述べない。
